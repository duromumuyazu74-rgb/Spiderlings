# 两个原生机制算例

这些例子用于校准推理与输出，数字不作为所有 Mod 的推荐默认值。原生事实及版本身份来自 [机制卡](../../kd-mechanics/references/verified-mechanics.md)。

## 抗性 Buff 从 0.5 改到 1

前提：5.4.92/5.5.0 的已核实倍率函数；该消费者直接把线性抗性 s 传入函数；其余修正相同。

`s=0.5` 时伤害乘数是 2/3，`s=1` 时是 1/2。改动后的该部分伤害是原来的 `(1/2)/(2/3)=0.75`，即下降 25%。不能表述为“抗性翻倍，所以伤害减半”。理想连续伤害下的有效生命相对增加 1/3；离散攻击取整和其他机制会改变实际击败回合数。

如果这是同 ID Buff 重施加，需先核实是否替换及 duration；如果是不同 ID 同 type，需核实聚合结果；如果消费者传的是 `-s`，应重新计算方向。这些条件比给定的候选数值更重要。

交付可写成：当前 0.5，候选 1；目标是减轻该类伤害 25%；源码计算已成立，目标构筑的实际生存回合与控制副作用待原生遭遇验证。

## NPC 绑定从 25% 增加到 30%

前提：满血、maxhp=100、`Enemy.bound` 可用、无高抗性标签、未监禁；按 `KDBoundEffects` 读取等级。

绑定量 25 返回 0，30 返回 1。这不是平滑的“多 5% 控制”，而是跨过严格大于 25% 的等级边界。对 `unflinching`，30 仍未跨过 50；对 `unstoppable`，第一阈值在 75 以上。低血量分支还会改变结论。

策划应比较相关标签与伤势下的阈值、实际挣脱与再次施加速度。最终绑定材料、累计量、消耗和反制窗口属于 Mod 设计；不能只调整一个比例就宣布所有 NPC 强度一致。
