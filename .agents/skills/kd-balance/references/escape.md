# 玩家脱困分析

在调整拘束、比较 Cut/Remove/Struggle、研究密度恢复或评估限时脱困时读取。先确认活动 checkout 与实际加载的 ZIP；工作区主目录可能仍是旧分支。用该 checkout 的参数与原生消费链，不把旧版固定行动次数规则带入已改用原生进度的版本。

## 先确定分析层次

- 单件基线回答字段怎样影响进度；完整穿戴回答组阻塞、工具与内外层顺序；有敌人的实际地图回答修补、受击、追捕和离场。按本次问题选择，单件成功不能证明监牢可逃。
- 将原生数据字段、Mod 事件与延迟回调一起追踪。`escapeChance` 参与有效速率、限制与成功门槛，不能直接当每次独立成功概率。`limitChance` 会进入进度限制公式，不是字面上的固定进度上限。
- 下限是带条件、可覆盖的规则。查 `struggleMinSpeed`、`speedMult`、`alwaysEscapable`、亲和、工具与原生延迟分段；最终新增进度还可能被 Mod 缩放。先用实际参数做对照，再判断某个小数值是否被下限抹平。
- 一次输入、延迟子回调与世界回合分别计数。时间和成本从真实调用观察；不要把一次操作固定换成四个回合，也不要让子回调重复计入一次性成长或扣减。

## 复用实验入口

Spiderlings 的 [脱困实验说明](../../../../docs/research/escape-model/usage.md) 提供 `analyze:escape`，复用现有 compatibility runtime、Mod ZIP 加载与共享准备环境。输入计划支持配对种子、完整穿戴、初始密度、静候策略及临时参数候选；也能在复制存档上观察指定拘束。原生事件、工具要求、支出、恢复及延迟结算均保留，实验不会为每次尝试补满资源。

需要监牢整体结果时，用说明中的 `mature-prison.json`，分别核对拆茧和 `route` 返回来源的结果。它以真实付费施工生成四层并保留现场敌人，准备干预与资源起点写入 `fixture`；已知地图的固定脚本路线不等于最优玩家策略。

需要复现历史结论时，读取 [原始 5.5.4 notebook 与当前适配记录](../../../../docs/research/escape-model/assessment.zh-CN.md)。原件及导出仅供历史对照；其中关闭事件的函数替身和内置 fallback 不作为当前 Mod 的实测结果。常规调参直接用当前实验入口，不默认加载或执行归档中的整套引擎。

比较候选时明确总回合预算是否包含静候与休息，保留没工具、阻塞、资源不足和超时样本。输出实际精力/意志支出、脱困动作数、密度轨迹和最终装备；少量配对样本用于找参数方向，不能声称总体成功率或精确 p95。

## 密度、叠层与限时脱困

从当前密度 owner 读取增加、保留期、衰减、缩放发生时机与存档规则。检查穿戴、自己的挣扎和延迟回调是否刷新衰减计时。把“静候后脱困”与“立即持续尝试”放在相同总预算下比较，同时检查节省的资源与消耗的机会窗口。

新成长机制先给每个已确认层数检查：零密度下是否保留正的合法收益；扣减是否仅对一次有效动作发生；本次净进度成功与新层成长、押送超时的顺序是否一致。未实现的 Boss 规则标为候选模型，只在隔离实验里变参。可计算部分用于收窄参数，完整场景仍以实现后的原生轨迹验收。

数值判断回到本次玩法目标。拘束已经拆除、围场已经破口、玩家已经离场是不同结果；结论只覆盖实际观察到的结果。
