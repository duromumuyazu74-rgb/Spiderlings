# 数值实验与判断

选能解决当前不确定性的最小方法。没有模拟器时可以完成源码推导和候选方案；只有结论依赖动态行为时才补探针或运行环境，不将先搭完整模拟器设为策划前提。

## 分析层次

- **静态计算**：从已核实公式算阈值、倍率、候选池归一化和资源预算。前提变化即失效。
- **原生函数探针**：执行目标版本函数，显式列出替身依赖；与实际入口相连的时序仍需验证。
- **完整运行**：隔离浏览器/存档、固定 Mod 加载集合与已知设置，记录实际回合和状态。不要使用真实玩家存档作为可写 fixture。
- **抽象模拟**：写明省略的规则，先用少量原生轨迹核对。自行编写的近似伤害/逃脱模型不是 KD 原生结果。

## 可比场景

复用项目已有合适的 harness；先检查它的输出位置和加载方式。一些历史 scratch helper 的缺文件分支会往官方游戏根编译，不能直接复用该分支，应把构建输出改到本次 scratch。

对照前后保持场景、构筑、初始资源、策略、预算和观测窗口一致。能控制随机数时记录种子及随机来源；相同种子在新增随机调用后可能不再对应相同遭遇，必要时固定场景/初始状态或独立随机流。不能控制时记录重复运行分布和样本数，结论随不确定性收窄。

选实际相关的策略：正面攻击、预警后撤离、控制后脱离、带工具逃脱、保留资源或等待。策略只使用它被允许看到的状态；一个弱脚本没有找到反制，不证明玩家无法反制。

## 统计口径

报告样本单位（回合、遭遇、楼层、整局），避免把同一局的相关回合当独立样本。按问题给均值/中位数、尾部分位数、成功率及不确定性。样本不足估尾部时直接列原始结果或范围，不能以五次测试声称精确 p95。

记录超时、失败和未脱困样本；限定时间内未脱困属于截尾观察，不能删掉后只统计成功者。二项结果可用 Wilson 区间，连续结果可用恰当的配对分析/Bootstrap；方法按样本结构选，不设通用最低次数或用 min–max 不重叠充当显著性检验。

解析概率有适用条件：独立、每次相同成功率 p 的尝试才有 `E[N]=1/p` 与 `P(N>n)=(1-p)^n`。KD 的进度、资源、加层和敌人反应会改变 p，因此这只是比较基线，不能直接作为真实逃脱时间。

## 判断与收尾

预期改进要对应设计指标，且查看相关代价：例如更短击杀时间可能伴随更长控制锁定；平均脱困变快可能掩盖无工具构筑的长尾。没有观察的体验结论标为设计判断。

记录版本/文件身份、Mod 状态、场景、策略、种子或随机限制、输入参数、样本数、指标、生成命令及证据路径。只有相关编辑、失败或未解问题才扩展/重复测试；所属产品的必需检查照常完成。
