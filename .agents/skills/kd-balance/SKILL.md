# KD 数值策划

把预期玩法转为有依据的参数与可检验结果。支持数值方案、已有实现调优和版本更新计划；纯程序故障先查机制，纯文本或资源修改无需数值流程。

沿用已确定的玩法目标、游戏补丁和 Mod 状态。需要确认字段含义、公式或原生基准时配合 [kd-mechanics](../kd-mechanics/SKILL.md)，采用其 [版本证据规则](../kd-mechanics/references/versions.md)。以 5.4.x 为基础，对照 5.5；不把一个补丁的参数效果推广为整个系列。

## 设计决策

先明确玩家在什么场景做什么选择，以及想改变的体验：例如“预警后有撤离机会”“控制能救场但无法无成本循环”。从同版本、同职能原生对象或已有 Mod 基线选参照；已有目标足够时直接推进。

核实控制结果的字段和消费链，分开**实现缺陷、规则缺陷、参数偏离**。事件重复触发或候选资格错误先修契约；正确规则下的强度偏离才调数值。方案需要规则变化时说明收益与代价，不默认扩大到重设计。

## 完成标准

数值方案给出当前/建议值或候选范围、单位、来源、理由、预期改变、受影响分支及验证办法。精确数值缺依据时标为候选，完成可计算部分并指出决定它需要的最小观察。无需为小改动生成完整 GDD 或统计报告。

实际调参请求包括实现、相关验证和受影响参数文档同步，沿用所属产品流程；调查或计划请求以方案和证据交付。结果区分原生实测、函数探针、近似估算和设计判断；“测试通过”不能直接写成“已经好玩/平衡”。

需要维护方法来源时见共享的 [构建依据](../kd-mechanics/references/design-sources.md)。
