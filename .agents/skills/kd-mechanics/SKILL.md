# KD 机制与版本向导

把玩法问题追到指定版本的实际执行路径，交付可供实现或决策的证据。用户的明确版本优先；此工作区以 **5.4.x 为基础，5.5 为差异对照**。5.4.92 的结果只证明该补丁，不能自动推广到整个 5.4.x。

先沿用任务中已确认的版本、Mod 和运行环境。未确认时读 [版本与证据](references/versions.md)，用版本标记及相关文件指纹定位输入；目录名和 Mod 的兼容声明只是线索。

## 按问题深入

| 问题 | 读取与产出 |
| --- | --- |
| 某行为怎样发生、代码从哪里接入 | [机制地图](references/mechanism-map.md)：定位领域，追踪数据定义 → 注册/缓存 → 调用者 → 状态变化 → 消费者。 |
| Buff、倍率、NPC 绑定等易误解语义 | [已核实机制](references/verified-mechanics.md)：复用对应版本事实，再检查本次调用条件。 |
| 5.4.x 补丁差异、迁移到 5.5、更新调查 | [版本迁移](references/migration.md)：建立能力差异与受影响 Mod 接点，交付适配建议和验证范围。 |
| 敌人强度、控制时长、逃脱、掉落或经济调参 | 配合 [kd-balance](../kd-balance/SKILL.md)，本技能负责原生语义与公式证据。 |

只打开当前分支所需的资料。已有证据足以回答时直接使用；新假设、文件变化或版本变化才重新核对。

## 机制调查的落点

对关键结论说明：**哪个版本、什么条件、哪个符号、怎样改变状态、什么证据支持**。签名存在只证明入口存在；参数含义要读消费处，事件要读发送处及处理表，缓存要找刷新和失效点。用最小原生调用或运行轨迹解开源码仍无法判定的问题。

区分源码事实、原生函数探针、完整运行观察和设计推断。缺少某版本时继续可完成的分析，明确哪些结论待核实。需要依赖未取得的行为才能安全实现时，只暂停该部分。

调查请求交付证据与建议；实现请求把调查结果带回所属产品，继续实现、相关验证及受影响文档更新。现有 `kd-mod-development` 和产品 `AGENTS.md` 负责开发与交付流程；本技能不新增发布流程。官方游戏和第三方参考只读，探针、编译输出和浏览器数据放所属工具或隔离 scratch。

新增可复用机制知识时，仅记录有版本依据的结论、符号和验证限度。维护本技能的来源与 Astra 取舍见 [构建依据](references/design-sources.md)，普通 KD 任务无需加载。
