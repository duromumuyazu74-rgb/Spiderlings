# 版本差异与更新调查

从目标 Mod 用到的行为开始比较：内容注册、事件、状态、资源、存档、数值公式、模型/资源生命周期。沿用现有接口清单；没有清单时从实际调用与挂钩提取。对照旧版/新版的调用方与消费方，避免只比函数签名。

每个实际影响用一行记录：`接点 | 旧补丁行为 | 新补丁行为 | Mod 影响 | 证据 | 适配/验证`。按“阻断运行、改变玩法、表现变化、无影响、待核实”排序；数据记录变更与引擎算法变更分别指出。签名相同也可能时序不同；版本号判断不能替代能力和行为核对。

优先采用两端共同的原生契约。确需适配时，在 Mod 自己的边界集中处理，标记支持的补丁与失效条件；已有上游修复时调查是否可撤掉旧补丁。用户只要求计划时交付可实施计划，实际修改沿用实现请求的授权。

## 本轮可复用的差异实例

5.4.92 `out/main.js::KinkyDungeonTickBuffs` 与 5.5.0 `Game/src/effect/KinkyDungeonBuffs.ts::KinkyDungeonTickBuffs`：

- 对带 `resetDurationTime` 的 Buff，5.4.92 在 duration 为 0/负值时进入重置，计算 `newPower` 后没有回写 power；5.5.0 在 duration ≤ 1 时也进入，并在保留 Buff 的重置分支写回 power。
- 5.5.0 多出 `restore_dp` 内建分支和 `buff.flag` 的 flag 更新。5.4.92 同名函数没有这两个内建分支，仍要检查 Mod 是否自行扩展 `KDCustomBuff`。

相同输入 `{power:3, duration:1, resetDurationTime:3, resetDurationPower:1}`，一次 `delta=1` 的独立原生函数调用后：5.4.92 是 `power=3,duration=0`；5.5.0 是 `power=2,duration=2`。这是函数探针，不包含完整游戏的施加与消费顺序。依赖逐期衰减的 Mod 需要分别验证，两端不能复用未经核对的时长模型。

版本指纹见 [baseline.json](baseline.json)，探针限度与维护见 [已核实机制](verified-mechanics.md)。

## 5.4.x 的补丁区间

本地 5.5.0 `Game/Changelog.txt` 提供调查线索：5.4.46 楼层传递，5.4.81 路径斜杠，5.4.82 自定义 capture action 与返回值，5.4.83 NPC 持久化修复，5.4.91 闪避 token 下限。它们不是整段 5.4.x 的已验证兼容矩阵；取对应提交或安装包后确认实际差异。

## 验证选择

纯公式变化用边界值原生函数探针；生命周期变化看首次加载、重复注册、tick、跨层或读档中实际受影响的分支；资源变化用隔离原生加载器。只运行受影响的组合及所属产品必需检查。

计划应能回答改哪里、为什么、如何证明完成、哪些目标版本仍缺证据。缺旧版本时可以完成新版本分析、依赖提取和探针准备，把待取证范围写清；不将兼容声明或一种版本通过写成全部通过。
