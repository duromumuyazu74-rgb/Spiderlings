# Configure engineering workflows

Inspect the existing root rules, `docs/agents/`, context map and tracker convention. Use `docs/agents/issue-tracker.md` as the tracker authority: Spiderlings uses GitHub Issues; other workspace products retain local Markdown. Use `CONTEXT-MAP.md` for product ownership.

For requested setup or repair, update the existing instruction files and supporting documents directly. Ask only when choosing an unknown tracker or policy would materially change the user's workflow. Reuse prior authorization; drafting and writing local configuration do not require separate approval rounds.

Keep root pointers short. Put tracker mechanics in `docs/agents/issue-tracker.md`, status vocabulary in `docs/agents/triage-labels.md`, and contextual reading rules in `docs/agents/domain.md`. Check their links and describe the resulting configuration.
