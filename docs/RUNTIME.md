Native player recognition gates live pressure destinations; NPC awareness alone leaves only valid recorded coordinates. Existing paid-field ownership, native combat and Recovery remain authoritative.

## Shared native hooks

`Spiderlings.Hooks.wrap(owner, native, create)` preserves the supplied native function and returns a stable wrapper. Reinstalling an owner already present in that Spiderlings chain replaces its callback at the existing position. This keeps new callbacks aligned with newly registered events without accumulating wrappers. `describe(handler)` reports owners in installation order.

| Native function              | Installation order, inner to outer                    | Delegation                                                                                                                          |
| ---------------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `KDAIType.hunt.beforemove`   | `WebCaster.hunt`, `Cocoon.hunt`, `Spinner.beforemove` | Publishes qualified player contact after native sensing; Spinner coordination runs after existing movement hooks decline the actor. |
| `KDAIType.hunt.attack`       | `Spinner.attack`                                      | Field, lure, yield and wait decisions suppress the later native attack phase. Defense and delegated pursuit retain it.              |
| `KDAIType.hunt.spell`        | `Spinner.spell`                                       | Uses the same per-actor, per-world-turn decision as the attack gate.                                                                |
| `KDAIType.wander.beforemove` | `Cocoon.wander`, `Spinner.wanderContact`              | Publishes qualified player contact after forwarding to the original handler.                                                        |
| `KinkyDungeonTrackSneak`     | `Spinner.playerContact`                               | Publishes real positive-time player recognition at the native 0.5 threshold without adding detection progress.                      |
| `KinkyDungeonEnemyLoop`      | `Spinner.runtime`                                     | Native field construction, legacy training and capture are ordered delegates; every unhandled call reaches the original loop.       |

Each callback forwards the original receiver, arguments and result on its unhandled route. The registry tracks Spiderlings-owned wrappers only. It does not inspect or replace another Mod's private wrapper chain, and it is not a general-purpose Mod hot-reload system. Other compatibility hooks retain their existing owners and guards.

Capture admission is inspected without changing saved state. Native tick, movement, enemy and load events commit participant changes or interruption. Drawing can hide invalid previews, but cannot cancel capture, create retry timers, migrate fields or advance work. A lost contest creates no equipment. Each paid wrapping turn deposits 0.2 into the exact equipped item, and a source audit ends temporary control at zero sources without changing that item. The load handler audits schema-3 sources and the saved bag ID, reads deposited progress from the item and clears older capture state instead of inferring work. `phase()` and `isControllingPlayer()` expose read-only control state so recovery can pause without sharing source or leash ownership.

Recovery exposes read-only `wantsPursuit(source, target)` for eligible departed or slack sources that still need a fresh hit. Player and NPC adapters share `RecoveryCore.pendingSource`; AI checks this duty before construction and lure work. It follows only a currently natively perceived target or a matching native observation less than four positive turns old, otherwise delegating to native AI. A pending player duty can use `playerObservation()` even if its group is engaged with an NPC; shared player knowledge does not change that engagement. With a fresh report and the source's own native sensing of the player, Runtime can replace an NPC candidate with the real player for that pending duty. The native loop still decides recognition and attack. A pursuit request creates no source, leash or movement credit. A fresh player hit still requires a compatible collar and native equipment access; failure emits `SpiderlingsRecoveryAttachBlocked` without establishing a pull. Recovery records at most eight distinct successful hitters. Audits remove dead, nonhostile, incapacitated, distant or occluded sources and never reconnect them without another hit. One stable executor pays each pull operation. A shared composite uses its common core; unrelated fields use source majority, shortest valid route and stable composite ID in that order, then fall back to the executor when no live field remains. Crossing a contiguous built Spiderlings web run costs two paid pull actions per cell and moves only on the final action. Stand firm costs `5 + 2 * (sources - 1)` displayed stamina and blocks the next legal owned pull. The owned leash adds `0.05 * (sources - 1)` to native Cut, Remove and Struggle escape penalty. Native acceptance with 2/4/8 sources verifies the costs, escape penalty, resisted action, resumed pulling and source removal; [the observations](normal-test-acceptance.md) support retaining these values. External leash item data and native tether ownership remain unchanged. A Spinner cannot source player Recovery and NPC Capture at the same time; admission rejects either cross-over, and load auditing retains Recovery ownership when stale saved records overlap.

NPC Recovery uses the same pending-source, source, executor, destination and crossing functions but owns no carrier or inventory event. Its read-only pursuit request uses the already selected native target and supplies no live target coordinates to AI. `enemyMove` records an actual departure through a breached outer field before field entry handling. A later native Spinner melee must add Slime before one allowed owner attaches. The executor spends one operation and uses `KDMoveEntity(target, x, y, false)` for the single legal displacement; native and owned `pulled` guards prevent another movement that turn. Returning to a repaired common core ends recovery but does not create Capture strands. Combat attempts normal NPC Capture first on every later positive-Slime hit and clears Recovery only after admission succeeds.

The public runtime-boundary tests cover rule-only execution, shared hook composition and rendering without state writes. The complete watcher adds native-source compatibility tests. Final ZIP loading still requires the applicable in-game checks in the [verification matrix](../CONTRIBUTING.md#verification).

## Native Spinner field planning

The doorway line scenario remains a focused #28 fixture. Ordinary and infestation maps use the same paid builder operations after Rollout snapshots the map decision. Planning compares legal passages and enclosures near a recognized native observation, preferring the largest usable interior among eligible candidates. A passage still must intercept an actual entrance-to-exit route through its capture interior, including suitable doorways, junctions and narrow corridors. An unavoidable route ranks above a route with a meaningful detour; merely facing the player or blocking adjacent mouths does not establish interception. A legal enclosure competes on usable interior space alongside passage candidates. Existing autonomous line plans retire their owned topology and reselect a field; explicit authored line fixtures retain their behavior. Each handled construction pass performs one operation and rechecks terrain, protected metadata and actor occupancy.

The projection uses a non-immobile `SpiderlingsSpinnerTrap` enemy with `SpiderlingsWebTraversal` as its native path condition and the native `scenery` tag. KD 5.4.92 and the pinned reference apply swap admission after a successful path condition; the structural tag admits the Spiderling to the web cell. Ordinary enemies fail the condition and remain blocked. A Spiderling accepted by the condition enters the proxy cell without removing or swapping the web. One actual actor may stand on the web; another actor cannot enter that occupied cell. Reconciliation orders proxies before actors so native cached target lookup selects the actor when both share a cell. Direct web damage still requires the selected proxy identity. Projectiles and sight use the underlying floor tile. The adapter stores lines, passages and enclosures in the same schema-2 physical graph and reconciles exactly one proxy per solid cell. Native enemy drawing selects `SpiderlingsSpinnerTrapTop`, `Side` and `Corner` pieces from the declared perimeter, with camera-aware placement and Normal/Pink selection. The old WebCell name exists only for native save hydration; load reconciliation replaces it while retaining entity identity and field durability. Independent ground traps, snare IDs and stepping-triggered slow are removed, including their old owned tile triggers and buffs.

Autonomous planning captures the map seed, forms groups from hostile capable Spinners within ten reachable steps and saves selected plans for travel. Nearby idle groups can merge into an existing field, prioritizing groups below two available workers. Merge distance measures the donor members' actual positions against the receiving site; a future plan center does not stand in for a distant worker. An uncommitted group may join a passage with fewer than four members from up to twenty reachable steps. Incoming helpers retain native travel and distinct rally/work reservations. Field space supplies distinct standby positions rather than a worker quota. Stations lie within two Chebyshev tiles of a gate, outside the interior, web boundary, protected or locked cells and other active planned web cells; a single-cell external gate approach stays clear. Live rally routing still checks reachability and occupancy. Crew members remain assigned to their invested or completed field, including when waiting space is scarce. A donor with paid construction, preparation or surviving built structures cannot merge away from its field. Before paid work begins, a new recognized observation can redirect an approach after at least four coordination turns: the target changed, moved at least four tiles from the planning observation, or reversed its recorded direction. The same crew replaces only that unpaid plan. Observation changes do not relocate invested or completed fields; actual invalid terrain still follows the existing invalidation path. Capture, Recovery, wrapping and task-nest defense keep their priority. No entity is removed or teleported. Each transition into `ready` recalculates waiting-gate assignments once from current member positions, then keeps them stable. Gate allocation accounts for the remaining uncovered mouths. Membership changes or a saved partition made unreachable by a stationed coworker trigger repartition; ordinary waiting does not. If coworkers prevent a complete actor-avoiding route, an incoming worker may approach along the free prefix of the native terrain route; the next-step occupancy check still prevents passing through any actor. Capture, recovery and nest defense prevent reassignment, and task-nest ownership restrictions remain in effect. Consolidation reduces duplicate fields without imposing a global field cap.

Candidate analysis reads floor topology, protected and locked metadata, entrances, exits, native walls, actor occupancy and member origins. `SpiderlingsSpinnerPassagePlanner.js` shares static connectivity, bounded route proofs and cached distances across groups and turns; terrain or relevant metadata changes invalidate that analysis. No-site results wait for a geometry or relevant occupancy change before retrying. Rollout records the selected passage or enclosure without replacing topology. A lone Spinner may construct a field, but capture still needs two legal sources and a real native hit. See [passage algorithms and proof limits](spinner-passage-algorithms.md).

`afterDamageEnemy.dmgDealt` is the only durability input. Reconciliation then overwrites surviving proxy HP from topology and removes breached cells. Every solid-cell change sets `KDUpdateEnemyCache` and replaces both `KDPathCache` and `KDPathCacheIgnoreLocks`; `KDUpdateDoorNavMap()` alone is insufficient for the second cache in this patch. `afterLoadGame` reuses one valid proxy per cell, drops duplicates and creates missing projections without changing saved HP or ownership. Positive `tickAfter` events on the active map alone advance the final-owner collapse age.

Mobile actors tagged `spiderlings` or `spider` receive 1.5 times ordinary movement credit only when their live destination is an intact Spiderlings-owned web. Credit remains fractional across attempts; a blocked move cannot earn the extra credit, and leaving the web uses ordinary movement. No MoveSpeed buff is applied, so attack, spell, construction and wrapping budgets retain their own cadence. Spider pursuit uses a separate actor-aware weighted route with 2/3 base cost for owned-web steps, including visible-target direction choice. Web changes, actual actor moves and load clear its cache. Other actors and unrelated webs retain native routing.

## Native passage fields

A passage saves its interior, grouped gate cells and borrowed native-wall cells in the existing schema-2 graph. Its rectangular interior is one to three cells per side, with two to four straight mouths. The complete eight-neighbor perimeter must consist of declared gates or actual native walls, including diagonal escape routes. Native doors, protected objects and unknown obstacles cannot serve as borrowed walls or web cells. The adapter rechecks the live terrain before paid work and capture admission. Losing a borrowed wall makes the field breached without creating a replacement.

All passage gates start open. Each gate takes a paid preparation action, which produces a faint Normal/Pink drawing only; no blocking or damageable entity is created. Prey entering the declared interior arms closure. Workers pay one action for each gate cell and another to connect each complete gate. Occupied cells wait. Only a fully closed valid field can admit a later qualifying melee hit. While sealed, support workers share the group's native last-known position only while it is less than four turns old and inside the field. They physically move toward nearby unoccupied cells, including gate and interior cells, without the waiting-gate partition limiting their approach. This movement does not grant capture sources or replace native melee admission. Target departure disarms closure and schedules paid reopening of the designated travel gates.

While prey remains outside and closure is not armed, at least two gates are designated open. A native observation aged less than four turns can choose the entrance nearest the last-known approach and a separate through gate toward the floor exit. Adjustments require a ready, undamaged field, no engaged capture/recovery sources and at least eight turns since the last change. Newly required openings are physically reopened before other mouths may close. Selection alone never places, removes or heals web cells. Broken gates retain their four-positive-turn rebuild cooldown; rebuilding and repair still consume actions. A saved entry or departure change cannot keep an obsolete close/reopen job alive.

Old single-entrance enclosures keep their geometry, construction and HP when loaded. Passage state adds gates and native-wall references without migrating them into a different field shape. Graphical objects, path caches and the static passage index stay outside saves. This ordinary test feature is separate from the `prison.alpha.N` experiment.

## Native enclosing-field slice

Issue #92 uses the same map-owned topology and `SpiderlingsSpinnerTrap` projection as the doorway line. Every declared enclosure is a saved simple orthogonal polygon. New autonomous enclosure candidates try radii three, two and one for legal 7-by-7, 5-by-5 and 3-by-3 outer footprints. All selected concentric layers are declared together, with `constructionOrder: "outer-first"`; saved layer IDs remain inner to outer and the innermost one-cell common core remains authoritative. One owner may build and close the field; every segment, closure and repair consumes a paid action. Existing invested rings remain in place and can gain legal outer layers without rebuilding their completed cells. New autonomous rings leave aligned gates open until prey enters the common core. Existing auto-sealed fields retain their sealed-inner-ring expansion rules. Player Capture strands retain their separate two-source admission requirement and use only the inner interior cell for a minimum field.

The physical graph expands boundaries to unit edges, merges equal edges and coalesces collinear spans only while owner sets match. Original polygon vertices remain real anchors. Overlap splits and crossings are junctions without anchor HP. Identical and partial overlaps therefore share one HP pool per physical span and one native proxy per occupied cell.

For an outer-first composite, builders complete an outer body before selecting work in the next smaller inner body. `nextWorkAction` reverses only construction priority; reopening, containment, capture core and saved layer numbering retain their existing meaning. Each autonomous ring retains one aligned entrance into the common core. A living hostile player or non-Spiderling NPC inside that core arms only that composite's closure; nearby actor movement does not cancel it. Closing each gate requires one paid cell operation and one paid connection operation. Once prey leaves or disappears, paid reopening restores the entrances, including partly closed gates. Completed body cells remain. Declared containment, outside-field reachability, outside-composite reachability and the route to the floor exit are separate queries. A crossing without a declared polygon is never a capture field.

Live owners may spend one action to restore 10 percent of a damaged structure's maximum HP. A destroyed anchor or link waits four positive active-map turns before paid rebuilding. Retired-only work is not repaired. The final valid owner still starts the 20-turn collapse count. `afterLoadGame` restores partly built, sealed and breached graphs and reconciles proxies idempotently.

The pinned 31-by-21 regular-room test keeps start `(2,10)`, exit `(28,10)`, worker starts `(11,9)` and `(12,11)`, boundary `(20,5)-(24,5)-(24,13)-(20,13)`, core `(22,9)` and gate `(20,9)`. Arrival-inclusive 2/4/8-worker results are 25/19/15 native world turns; legal-worksite starts take 15/6/4. The prototype references are 27/20/18 and 12/6/4. Native occupancy avoidance and movement to remaining work account for the differences. The test retains blocked and unfinished measurements instead of discarding them.

Debug scenarios use the same enclosure and controller runtime as Rollout. They admit Capture strands only after a qualifying native Spinner hit; field damage after admission does not cancel those strands. Scenario control saves selected actor IDs, target ID, awareness and the pre-existing encounter so a real load can resume controls and teardown restores unrelated state.

## Native lure-coordination slice

Issue #31 extends each saved group with one engagement. Test.75 adds one current-map player report at `encounter.ai.playerObservation`: `x`, `y`, `dx`, `dy`, `age`, `source: "native"`, player target identity and `reporterId`. `reportPlayerContact()` is its publication interface; `playerObservation()` returns a detached usable copy. Only living, actionable, hostile Spinner, Jumper, WebCaster, Tunneler, NestEntrance and MageSpiderlings can publish. Allied, party, disabled or helpless actors cannot publish hostile intelligence, and NPC targets cannot substitute for the player. Before planning on a positive world turn, `refreshObservations` scans eligible actors using native target choice, line of sight or actual hearing and recognized-contact eligibility. Capture, Recovery and NPCWrapping duty holders can report credible contact without surrendering their control duties; busy actors are not selected as lures. Native acquisition and zero-delta recognition sampling use detached observers, so sampling adds no awareness or detection progress. The real positive-time `KinkyDungeonTrackSneak` result at the native 0.5 threshold can publish newly recognized player contact during that same enemy loop; NPC-combat awareness does not replace this player-specific recognition gate. Native `hunt` and `wander` beforemove reports add visual classification. Spinner base `visionRadius` remains eight; buffs, blindness and native stealth recognition still apply.

A valid player report supplies the same recorded position, direction and age to every hostile Spinner group for site planning, entrances, waiting positions, pressure and Recovery pursuit. Empty or player engagements receive the report; ongoing NPC engagements retain their native targets and local observations. `groupObservation(group)` returns a detached shared player snapshot when eligible, otherwise the group's matching native observation. A member without personal contact uses the recorded cell rather than hidden live coordinates. Shared visual reports use `shared:<reporterId>` so group sight and pressure can respond without impersonating the lure's personal sight or writing native `aware`/`vp`. Hearing can refresh a recognized nonvisual position but does not reset sight counters. The detection turn stores age zero; positive `tickAfter` events advance report age once, ages zero through three are usable, and age four removes the report. Hidden unrecognized movement, nonpositive updates and loading do not renew it; the active-map encounter owns its scope. Eight completed turns without actual or shared native sight switch the lure to delegated native pursuit, while continuing credible hearing still guides investigation of the recorded position. For a passage group, twelve turns without sight and no native sensing contact on the current turn end the engagement so its lure can return to field work or waiting. While prey is visible, six completed turns without a closer approach to the saved field waypoint or additional paid construction/repair switch the lure to pressure pursuit. Renewed sight does not switch pressure back to lure. Core entry still prioritizes assigned paid gate work before native melee. Disabled, helpless, dead, missing or no-longer-hostile role holders are audited before actions and replaced deterministically.

The lure uses native paid movement to vacate pending gates and work cells, avoid adjacent contact when a legal choice exists and retreat toward the saved field waypoint. Other capable members retain #29 reservations and use #30's enclosure scheduler. On common-core entry or withdrawal, outstanding paid gate work temporarily includes the lure and takes priority over adjacent defense, so even a lone builder can close and reopen its entrance. Other adjacent, actually perceived hostile targets select native defense for one pass; the native attack accumulator decides whether a hit is ready. Every other handled lure, movement, work, yield or wait decision blocks the later native attack and spell phases for that actor and world turn.

`afterLoadGame` removes invalid members and targets, expires stale last-known data, replaces an invalid lure, clears transient decisions and deduplicates saved task and work-cell claims. It neither selects a new field nor creates a job. `setupCooperative()` and `spiderlingsSpinnerCooperative` enter this same production path for manual testing. Automated evidence and the remaining graphical test limit are recorded in [Spinner lure coordination evidence](spinner-lure-coordination.md).

NPC wrapping labels require a visible target. Strands also require a visible source, using native enemy visibility and tile vision. Drawing does not clear wrapping progress when either endpoint is hidden.

## Native web targeting and zero-time refreshes (test.60)

Owned Spinner web proxies are valid Maidforce rivals and projectile targets. They use the native permanent `targetedForAttack` flag, and override IceWall's `lowpriority` rule so a visible player cannot suppress an NPC's web target. These changes apply only to marked Mod projections; species membership, global faction relations and native scenery definitions remain separate.

Recovery path selection first asks native pathfinding for an ordinary obstacle-avoiding route. If none exists, it asks for a cardinal spider route and uses the existing paid web-crossing rules. Spider movement discounts must not redirect a pulled player from an open breach to a blocked diagonal corner.

Native load calls `AdvanceTime(0)`. Spinner's before-move hook returns without decisions or construction on nonpositive runtime delta, preserving saved credit, position and partial topology. The final native matrix checks snapshot equality across reload and no additional work on zero-time updates. ## Mage visual delivery and geometry (introduced in test.66)

`MageSpells` publishes each resolved mark blast or Collapse once to `SpellVisuals.burst(effect)` at native resolution. The renderer copies only the footprint into map-local transient state, deduplicates a repeated event object, and times the flash for 520 ms from resolution. It no longer discovers resolved bursts by polling saved `blasts` during drawing. Gameplay records and damage timing are unchanged. Continuous positive ticks without drawing may expire the saved one-turn record while the visual remains available within that real-time window.

The following describes the test.66 contract; test.67 supersedes its numeric display and area layer as described below.

`afterLoadGame` and map replacement clear transient delivery; resolved save records are not replayed. Persistent Hex/Rune/Collapse warnings and countdowns still restore from native gameplay state. Events whose complete footprint is hidden at delivery are discarded; every rendered cell continues to respect current fog. This is an intentional one-shot policy, not a new save schema or a cosmetic replay queue.

The renderer retains at most 64 immutable footprint arrays in a map-local LRU, with weakly held boundary edges. Width, height, world origin and cut corners are part of the key. Camera projection, fog, alpha, palette and countdown values are recomputed each frame. Reset clears this cache. Area Graphics remain at 2.4; mark/weapon-silk actor Graphics use a separate 2.5 layer; hit/countdown feedback remains at 2.6. Both Graphics are destroyed on reset. Native sprite and shared-texture ownership stays with KD.

Rune legal-cell selection creates a local occupancy set on every query, preserving row/column order. Actual casting queries again, so changed actors, active bullets, terrain and LOS are revalidated without a cross-turn cache. Rune limits, probabilities, targets, paid actions and saved phases are unchanged.

## Mage fog correction (test.69)

Cross-cell Mage core and burst sprites use camera-projected per-visible-cell Graphics masks. Fully visible sprites have no mask; entirely hidden sprites do not draw. Masks are Mod-owned and removed when unused, on map changes or load reset. Native fog cannot be assumed to hide these Mod sprites, because the native fog board is below their drawing layer. Warning masks stay fixed and silk still gathers inward. Frame-local vision caching never affects resolution-time burst visibility checks outside draw. Entirely hidden warnings return before geometry/sprite work. The unit regression compares all 24 segments under fixed visibility. Native gathering acceptance matches direction and normalized brightness identities for the same segments visible at both samples; it does not use a mean over changing fog sets. Partial-fog cropping receives separate evidence.

### Explicit debug stair passage

Teleport to stairs grants a transient session-backed token to the current active Infestation or Hunting Grounds map only after the actual native cheat callback/legacy HUD action succeeds and places the player at the end position. The shared Floor Selection adapter exposes `canBypassObjective()` to both the escape-method check and the downward-stair guard. Quest quotas are not a cheat detector; objective completion, target entities and rewards are untouched.

KD 5.5.3 uses the named `debugtelestairs` button callback. KD 5.4.92 uses the original debug-only HUD click rectangle; the adapter verifies that native handler branch exists and wraps it rather than duplicating the cheat. A committed nonzero stair advance removes the map token and its session grant. A zero-advance side-room return retains it. Loading clears all session grants, so serialized tokens cannot leak debug access.

### Player recovery strand rendering

Recovery owns a separate draw event keyed by its controller, with the same normal/pink tether texture and camera-coordinate convention as Capture. It does not write `player.leash` or run a logic audit during drawing. Source sprites have per-visible-cell pixel masks; fully hidden or dead sources do not draw. A slack carrier has no controlled strand. Capture temporarily suppresses Recovery rendering. Control clearing and load dispose masks and fallback graphics; every frame hides unused sprites.

A fresh eligible successful hit reports attached source count or rejected native equipment admission. Rejection still consumes the recovery hit, leaves departure eligibility available and establishes no pull. The new owned carrier still requires a compatible collar; existing usable external leashes retain native compatibility, lock/progress and movement ownership.

### Hex mark world-turn continuity

Active Hex still lasts three turns over its unchanged 4-by-4 cells. A mark gains at most one layer per actual world turn across overlapping fields, caps at three, and retains the existing `2 + stacks` expiry refresh (3/4/5 turns). Leaving or field expiry stops refresh. A consumed mark now accepts the next actual turn inside the active area; a queued older burst still resolves independently, and no same-turn rearm is granted.

The saved spell state records `lastNativeTick` alongside its local clock. Repeated positive `tickAfter` events in the same native turn, including after load, do not advance spell timing or restack. Legacy states without this field admit their first genuine tick. Rendering never advances this state.
