# Runtime ownership

The manifest owns script loading order. Runtime scripts remain plain JavaScript in KD's native global environment, sharing the `Spiderlings` namespace. This structure applies to the `0.92.36-test.65` development package.

Core precedes encounters and WebCaster movement. Webbing data precedes Webbing rules, which precede the native Webbing adapter. Tests explicitly load these dependencies; the independent manifest allowlist test protects delivery order. Rule-only tests load data and rules without registering enemies, items, native hooks or game events.

## Shared native hooks

`Spiderlings.Hooks.wrap(owner, native, create)` preserves the supplied native function and returns a stable wrapper. Reinstalling an owner already present in that Spiderlings chain replaces its callback at the existing position. This keeps new callbacks aligned with newly registered events without accumulating wrappers. `describe(handler)` reports owners in installation order.

| Native function              | Installation order, inner to outer                    | Delegation                                                                                                                    |
| ---------------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `KDAIType.hunt.beforemove`   | `WebCaster.hunt`, `Cocoon.hunt`, `Spinner.beforemove` | Spinner coordination runs after native sensing and after the existing owned movement hooks decline the actor.                 |
| `KDAIType.hunt.attack`       | `Spinner.attack`                                      | Field, lure, yield and wait decisions suppress the later native attack phase. Defense and delegated pursuit retain it.        |
| `KDAIType.hunt.spell`        | `Spinner.spell`                                       | Uses the same per-actor, per-world-turn decision as the attack gate.                                                          |
| `KDAIType.wander.beforemove` | `Cocoon.wander`                                       | Unrelated calls reach the original handler.                                                                                   |
| `KinkyDungeonEnemyLoop`      | `Spinner.runtime`                                     | Native field construction, legacy training and capture are ordered delegates; every unhandled call reaches the original loop. |

Each callback forwards the original receiver, arguments and result on its unhandled route. The registry tracks Spiderlings-owned wrappers only. It does not inspect or replace another Mod's private wrapper chain, and it is not a general-purpose Mod hot-reload system. Other compatibility hooks retain their existing owners and guards.

Capture admission is inspected without changing saved state. Native tick, movement, enemy and load events commit participant changes or interruption. Drawing can hide invalid previews, but cannot cancel capture, create retry timers, migrate fields or advance work. A lost contest creates no equipment. Each paid wrapping turn deposits 0.2 into the exact equipped item, and a source audit ends temporary control at zero sources without changing that item. The load handler audits schema-3 sources and the saved bag ID, reads deposited progress from the item and clears older capture state instead of inferring work. `phase()` and `isControllingPlayer()` expose read-only control state so recovery can pause without sharing source or leash ownership.

Recovery records at most eight distinct successful hitters. Audits remove dead, nonhostile, incapacitated, distant or occluded sources and never reconnect them without another hit. One stable executor pays each pull operation. A shared composite uses its common core; unrelated fields use source majority, shortest valid route and stable composite ID in that order, then fall back to the executor when no live field remains. Crossing a contiguous built Spiderlings web run costs two paid pull actions per cell and moves only on the final action. Stand firm costs `5 + 2 * (sources - 1)` displayed stamina and blocks the next legal owned pull. The owned leash adds `0.05 * (sources - 1)` to native Cut, Remove and Struggle escape penalty. Native acceptance with 2/4/8 sources verifies the costs, escape penalty, resisted action, resumed pulling and source removal; [the observations](normal-test-acceptance.md) support retaining these values. External leash item data and native tether ownership remain unchanged. A Spinner cannot source player Recovery and NPC Capture at the same time; admission rejects either cross-over, and load auditing retains Recovery ownership when stale saved records overlap.

NPC Recovery uses the same source, executor, destination and crossing functions but owns no carrier or inventory event. `enemyMove` records an actual departure through a breached outer field before field entry handling. A later native Spinner melee must add Slime before one allowed owner attaches. The executor spends one operation and uses `KDMoveEntity(target, x, y, false)` for the single legal displacement; native and owned `pulled` guards prevent another movement that turn. Returning to a repaired common core ends recovery but does not create Capture strands. Combat attempts normal NPC Capture first on every later positive-Slime hit and clears Recovery only after admission succeeds.

The public runtime-boundary tests cover rule-only execution, shared hook composition and rendering without state writes. The complete watcher adds native-source compatibility tests. Final ZIP loading still requires the applicable in-game checks in the [verification matrix](../CONTRIBUTING.md#verification).

## Native Spinner field planning

The doorway line scenario remains a focused #28 fixture. Ordinary and infestation maps use the same paid builder operations after Rollout snapshots the map decision. Planning prefers a passage that intercepts an actual entrance-to-exit route through its capture interior, including suitable doorways, junctions and narrow corridors. An unavoidable route ranks above a route with a meaningful detour; merely facing the player or blocking adjacent mouths does not establish interception. A legal enclosure remains the fallback. Existing autonomous line plans retire their owned topology and reselect a field; explicit authored line fixtures retain their behavior. Each handled construction pass performs one operation and rechecks terrain, protected metadata and actor occupancy.

The projection uses a non-immobile `SpiderlingsSpinnerTrap` enemy with `SpiderlingsWebTraversal` as its native path condition and the native `scenery` tag. KD 5.4.92 and the pinned reference apply swap admission after a successful path condition; the structural tag admits the Spiderling to the web cell. Ordinary enemies fail the condition and remain blocked. A Spiderling accepted by the condition enters the proxy cell without removing or swapping the web. One actual actor may stand on the web; another actor cannot enter that occupied cell. Reconciliation orders proxies before actors so native cached target lookup selects the actor when both share a cell. Direct web damage still requires the selected proxy identity. Projectiles and sight use the underlying floor tile. The adapter stores lines, passages and enclosures in the same schema-2 physical graph and reconciles exactly one proxy per solid cell. Native enemy drawing selects `SpiderlingsSpinnerTrapTop`, `Side` and `Corner` pieces from the declared perimeter, with camera-aware placement and Normal/Pink selection. The old WebCell name exists only for native save hydration; load reconciliation replaces it while retaining entity identity and field durability. Independent ground traps, snare IDs and stepping-triggered slow are removed, including their old owned tile triggers and buffs.

Autonomous planning captures the map seed, forms groups from hostile capable Spinners within ten reachable steps and saves selected plans for travel. Nearby idle groups can merge into an existing field, prioritizing groups below two available workers. Merge distance measures the donor members' actual positions against the receiving site; a future plan center does not stand in for a distant worker. An uncommitted group may join a passage with fewer than four members from up to twenty reachable steps. Incoming helpers retain native travel and distinct rally/work reservations. Each transition into `ready` recalculates waiting-gate assignments once from current member positions, then keeps them stable. If coworkers prevent a complete actor-avoiding route, an incoming worker may approach along the free prefix of the native terrain route; the next-step occupancy check still prevents passing through any actor. Capture, recovery and nest defense prevent reassignment, and task-nest ownership restrictions remain in effect. Consolidation reduces duplicate fields without imposing a global field cap.

Candidate analysis reads floor topology, protected and locked metadata, entrances, exits, native walls, actor occupancy and member origins. `SpiderlingsSpinnerPassagePlanner.js` shares static connectivity, bounded route proofs and cached distances across groups and turns; terrain or relevant metadata changes invalidate that analysis. No-site results wait for a geometry or relevant occupancy change before retrying. Rollout records the selected passage or enclosure without replacing topology. A lone Spinner may construct a field, but capture still needs two legal sources and a real native hit. See [passage algorithms and proof limits](spinner-passage-algorithms.md).

`afterDamageEnemy.dmgDealt` is the only durability input. Reconciliation then overwrites surviving proxy HP from topology and removes breached cells. Every solid-cell change sets `KDUpdateEnemyCache` and replaces both `KDPathCache` and `KDPathCacheIgnoreLocks`; `KDUpdateDoorNavMap()` alone is insufficient for the second cache in this patch. `afterLoadGame` reuses one valid proxy per cell, drops duplicates and creates missing projections without changing saved HP or ownership. Positive `tickAfter` events on the active map alone advance the final-owner collapse age.

Mobile actors tagged `spiderlings` or `spider` receive 1.5 times ordinary movement credit only when their live destination is an intact Spiderlings-owned web. Credit remains fractional across attempts; a blocked move cannot earn the extra credit, and leaving the web uses ordinary movement. No MoveSpeed buff is applied, so attack, spell, construction and wrapping budgets retain their own cadence. Spider pursuit uses a separate actor-aware weighted route with 2/3 base cost for owned-web steps, including visible-target direction choice. Web changes, actual actor moves and load clear its cache. Other actors and unrelated webs retain native routing.

## Native passage fields

A passage saves its interior, grouped gate cells and borrowed native-wall cells in the existing schema-2 graph. Its rectangular interior is one to three cells per side, with two to four straight mouths. The complete eight-neighbor perimeter must consist of declared gates or actual native walls, including diagonal escape routes. Native doors, protected objects and unknown obstacles cannot serve as borrowed walls or web cells. The adapter rechecks the live terrain before paid work and capture admission. Losing a borrowed wall makes the field breached without creating a replacement.

All passage gates start open. Each gate takes a paid preparation action, which produces a faint Normal/Pink drawing only; no blocking or damageable entity is created. Prey entering the declared interior arms closure. Workers pay one action for each gate cell and another to connect each complete gate. Occupied cells wait. Only a fully closed valid field can admit a later qualifying melee hit. While sealed, support workers share the group's native last-known position only while it is less than four turns old and inside the field. They physically move toward nearby unoccupied cells, including gate and interior cells, without the waiting-gate partition limiting their approach. This movement does not grant capture sources or replace native melee admission. Target departure disarms closure and schedules paid reopening of the designated travel gates.

While prey remains outside and closure is not armed, at least two gates are designated open. A native observation aged less than four turns can choose the entrance nearest the last-known approach and a separate through gate toward the floor exit. Adjustments require a ready, undamaged field, no engaged capture/recovery sources and at least eight turns since the last change. Newly required openings are physically reopened before other mouths may close. Selection alone never places, removes or heals web cells. Broken gates retain their four-positive-turn rebuild cooldown; rebuilding and repair still consume actions. A saved entry or departure change cannot keep an obsolete close/reopen job alive.

Old single-entrance enclosures keep their geometry, construction and HP when loaded. Passage state adds gates and native-wall references without migrating them into a different field shape. Graphical objects, path caches and the static passage index stay outside saves. This ordinary test feature is separate from the `prison.alpha.N` experiment.

## Native enclosing-field slice

Issue #92 uses the same map-owned topology and `SpiderlingsSpinnerTrap` projection as the doorway line. Every declared enclosure is a saved simple orthogonal polygon. The minimum outer footprint is 3 by 3 with one interior cell. One owner may build and close it. A completed body may gain a new outer ring one cell farther out, initially 5 by 5 and 7 by 7; every segment, closure and repair consumes a paid action. New autonomous rings leave aligned gates open until prey enters the common core. Existing auto-sealed fields retain their sealed-inner-ring expansion rules. Player Capture strands retain their separate two-source admission requirement and use only the inner interior cell for a minimum field.

The physical graph expands boundaries to unit edges, merges equal edges and coalesces collinear spans only while owner sets match. Original polygon vertices remain real anchors. Overlap splits and crossings are junctions without anchor HP. Identical and partial overlaps therefore share one HP pool per physical span and one native proxy per occupied cell.

Builders complete the inner body before adding an outer ring. Each autonomous ring retains one aligned entrance into the common core. A living hostile player or non-Spiderling NPC inside that core arms only that composite's closure; nearby actor movement does not cancel it. Closing each gate requires one paid cell operation and one paid connection operation. Once prey leaves or disappears, paid reopening restores the entrances, including partly closed gates. Completed body cells remain. Declared containment, outside-field reachability, outside-composite reachability and the route to the floor exit are separate queries. A crossing without a declared polygon is never a capture field.

Live owners may spend one action to restore 10 percent of a damaged structure's maximum HP. A destroyed anchor or link waits four positive active-map turns before paid rebuilding. Retired-only work is not repaired. The final valid owner still starts the 20-turn collapse count. `afterLoadGame` restores partly built, sealed and breached graphs and reconciles proxies idempotently.

The pinned 31-by-21 regular-room test keeps start `(2,10)`, exit `(28,10)`, worker starts `(11,9)` and `(12,11)`, boundary `(20,5)-(24,5)-(24,13)-(20,13)`, core `(22,9)` and gate `(20,9)`. Arrival-inclusive 2/4/8-worker results are 25/19/15 native world turns; legal-worksite starts take 15/6/4. The prototype references are 27/20/18 and 12/6/4. Native occupancy avoidance and movement to remaining work account for the differences. The test retains blocked and unfinished measurements instead of discarding them.

Debug scenarios use the same enclosure and controller runtime as Rollout. They admit Capture strands only after a qualifying native Spinner hit; field damage after admission does not cancel those strands. Scenario control saves selected actor IDs, target ID, awareness and the pre-existing encounter so a real load can resume controls and teardown restores unrelated state.

## Native lure-coordination slice

Issue #31 extends each saved group with one engagement. The target comes from the native enemy-loop argument after KD computes hostility and perception, so it may be the player or a hostile NPC. The first valid observation fixes the target and one lure. Later native target choices do not rotate that saved target. Disabled, helpless, dead, missing or no-longer-hostile role holders are audited before actions and replaced deterministically.

Only a qualifying observer copies a target cell into group state. The detection turn stores age zero. Positive `tickAfter` events advance the age once; ages zero through three are usable, and age four removes both the cell and direction. Eight completed turns without actual sight switch the lure to delegated native pursuit. For a passage group, twelve turns without sight and no native sensing contact on the current turn end the engagement so its lure can return to field work or waiting. A valid observation resumes or starts an engagement. Hearing can refresh the last-known cell, but only native sight resets the no-sight counters.

The lure uses native paid movement to vacate pending gates and work cells, avoid adjacent contact when a legal choice exists and retreat toward the saved field waypoint. Other capable members retain #29 reservations and use #30's enclosure scheduler. On common-core entry or withdrawal, outstanding paid gate work temporarily includes the lure and takes priority over adjacent defense, so even a lone builder can close and reopen its entrance. Other adjacent, actually perceived hostile targets select native defense for one pass; the native attack accumulator decides whether a hit is ready. Every other handled lure, movement, work, yield or wait decision blocks the later native attack and spell phases for that actor and world turn.

`afterLoadGame` removes invalid members and targets, expires stale last-known data, replaces an invalid lure, clears transient decisions and deduplicates saved task and work-cell claims. It neither selects a new field nor creates a job. `setupCooperative()` and `spiderlingsSpinnerCooperative` enter this same production path for manual testing. Automated evidence and the remaining graphical test limit are recorded in [Spinner lure coordination evidence](spinner-lure-coordination.md).

## Spell ownership and wrapping visibility

WebCaster direct and trail projectiles use their saved source ID and faction after the caster dies or leaves. Native hit bookkeeping, shield and resistance handling, and the per-turn trail allowance still apply; crossfire requires living participants. Mage area spells and runes check hostility before targeting the player. Hex fields, marks and delayed blasts retain the owner faction in map state; runes retain it on the native bullet. Living Mage sources use their current native hostility. Records predating test.54 without a saved faction retain the former Enemy fallback when their caster is absent.

NPC wrapping labels require a visible target. Strands also require a visible source, using native enemy visibility and tile vision. Drawing does not clear wrapping progress when either endpoint is hidden.

## Spinner capture artwork

Five paid wrapping operations still deposit 0.2 each in the equipped item. Rendering maps this progress onto seven full-canvas stages; it never deposits silk. The fifth operation removes temporary capture control immediately, while an item-ID-bound visual finish continues the remaining 500 ms tween. Interruption clears that finish, and loading restores saved progress without replay. The tail follows the growing upper edge, passes behind the character and tucks away at completion. The completed Stage7 exposes the feet and supplies its own upper edge; the former Band, Finished and Closure images are retired. [Artwork sources and loading](spinner-stage-art.md) describe both colors and lossless sheets.

## Native web targeting and zero-time refreshes (test.60)

Owned Spinner web proxies are valid Maidforce rivals and projectile targets. They use the native permanent `targetedForAttack` flag, and override IceWall's `lowpriority` rule so a visible player cannot suppress an NPC's web target. These changes apply only to marked Mod projections; species membership, global faction relations and native scenery definitions remain separate.

Recovery path selection first asks native pathfinding for an ordinary obstacle-avoiding route. If none exists, it asks for a cardinal spider route and uses the existing paid web-crossing rules. Spider movement discounts must not redirect a pulled player from an open breach to a blocked diagonal corner.

Native load calls `AdvanceTime(0)`. Spinner's before-move hook returns without decisions or construction on nonpositive runtime delta, preserving saved credit, position and partial topology. The final native matrix checks snapshot equality across reload and no additional work on zero-time updates. Gameplay and balance observations are in [normal-test acceptance](normal-test-acceptance.md).

## Player weapon silk and the reusable field (test.59)

Actual positive native Slime from tome/staff melee or their own spells feeds a saved enemy ledger. Visible map bands follow native interpolation and surviving silk, with the selected Normal/Pink palette. The staff never creates the tome set. A live hostile target receives the existing Lv1 Arm, Legs, Ankles and Belly pieces only when the tome's own silk independently meets native helplessness and can pay the native binding value of each available piece. Existing body groups, blockers and occupied native layers remain intact. Conjured pieces use already-applied binding; equipping adds no extra Slime, and removing them returns no inventory. Only a later successful tome hit may add pieces again. Native dressing selects the supplied wrist/closed-leg art only while those owned physical items exist.

The NPC legbag uses the direct Stage7 asset through the native model path. Player animation retains the seven-stage renderer. Color changes refresh loaded NPC model copies as well as the player. The bag covers above the ankles through the thighs, leaving feet and arms exposed.

`SpiderlingsSpinnerDemo` is no longer registered as a starting perk or start callback. Developers can still call `Spiderlings.SpinnerField.enter()` to enter the disposable flat field and reuse its reset/add controls; `SpinnerScenarios` retains the map-aware fixtures. These are test facilities, not an additional gameplay start.

A completed NPC wrap whose native removal was cancelled retains progress 3. Its next eligible native operation retries removal without another construction payment. The wrapper still occupies that operation and does not also attack or cast.
