# test.96 Spinner 架构改进

本次根据 2026-10-05 的 Spinner 行为与维修分工架构报告完成三项改进。工作延续 test.95 的职责修复。

## 职责与动作规则

合法维修继续由 AI 的职责判断保护。玩家 Capture 全队已参与时，仅为可达维修调出一名有效来源，至少留下一名，不重置已有计数。NPC Capture 保留非参与者维修，Recovery 与巢穴防御继续优先。后续补线、连接和耐久恢复沿用原维护成员。

Topology 现在承担线状场地任务生成，以及线、围场和通道动作的目标、待执行状态、维修性质、占格许可、门动作和统计分类。AI 删除独立的动作类型猜测及有效条件，只使用 Topology 结果分配可达工位和成员。NativeField 删除重复的目标推导，保留原生移动、施工信用支付、距离和路径检查、投影同步。

`inspectWorkAction` 的待执行判断复用 `legalAction`，使用不含瞬时占格的快照。任务预留后发生的占格、地形变化仍在实际执行时通过原生快照复核。冷却未满、门重新开放、场地退休和所有权失效不能保留无效维修。既有存档结构、任务键、进度和加载顺序保持兼容。相邻锚点之间没有中间格的付费连接仍保留。

## 测试

AI 测试新增真实 Capture、AI、Topology、NativeField 与 Runtime 的组合场景，原生设备查询由夹具提供。两名成员先成为实际玩家 Capture 来源，再分别遭遇轻伤和打穿边界。测试从 Runtime 的敌人循环和回合事件运行真实实现，要求实际付费维修、打穿后的继续补线、场地恢复闭合、至少一个来源和已有编织与挣脱计数。

新增 Topology 回归覆盖维修目标被占用、重建冷却、读档、退休和通道入口变化。既有原生 `spinner-maintenance` 场景继续验证两种损伤、真实支付和重建中读档。未增加全局调度或独立的薄分类模块。

四个相关测试文件共 144 项通过。最终包和双版本完整验收结果以 [COMPATIBILITY.md](COMPATIBILITY.md) 及交付报告为准。
