## 实现

`SpiderlingsPopulation.js` 负责特殊楼层所需队伍的预算、出生位置重验证、整队创建和失败撤回。它在 manifest 中先于 Encounters 加载，提供四个入口：

| 入口                 | 职责                                                                                   |
| -------------------- | -------------------------------------------------------------------------------------- |
| `prepareFloor(kind)` | 在原有时间点写入人口计划，返回上限、余量和必需人数。                                   |
| `planCrews(...)`     | 只读地查询整队出生格，不预占地图或配额。猎场可在放巢前用它评估位置。                   |
| `seedCrews(...)`     | 核对当前余量与候选格，创建必需队伍和可选巡逻队，失败时撤回本批出生并还原原有巢穴登记。 |
| `missingRoles(nest)` | 查询六人守卫编组缺失的物种及职责，供原有巢穴增援流程使用。                             |

猎场保留三支六人守卫和一支可选六人巡逻队；侵扰保留五个原始目标巢穴，其中两巢配置六人队。每支队伍仍是 Spinner×2、Jumper×1、WebCaster×2、Mage×1。起始 Perk 的六人小队有自己的 Tunneler 配置，继续独立处理。

楼层模块保留地图开凿、目标 ID、进入/退出、取消和状态发布。原生初始人口与游荡选择器仍在原位置安装，避免重构改变 hook 顺序。人口计划、巢穴编制和实体职责沿用现有存档字段。四人旧巢不被自动升级；增援计时、概率、权重及 Tunneler 终身额度保持。

配额不足时现在会在出生前拒绝必需队伍。例如已有一只移动蜘蛛、猎场上限为 18 时，剩余 17 格无法容纳 18 人守卫，直接取消。这条受控失败路径比旧版少消耗召唤、实体 ID 和随机数；它是预算前置检查的预期变化。

进层提示复用原生 `KDEscapeMethodDesc_*`，下楼受阻提示复用原有进度文本。英文及七种翻译说明原始目标巢穴、小地图红色任务标记及后建巢穴不计入目标。地图修饰符氛围文保留。红色标记仍受原生小地图显示范围限制，不新增全图导航或揭雾。

## 复审与修正

| 问题                 | 触发与影响                                                           | 修正                                                                           |
| -------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 原生召唤先插入再抛错 | 部分守卫已经进入实体列表，但召唤未返回它；只处理返回值会遗留半队。   | 撤回已返回的本批出生，以及当前召唤位置上可归属的同名新实体；恢复原有巢穴登记。 |
| 清理范围过大         | 异常路径若删除所有“开始之后新增”的实体，会误删其他 hook 创建的 NPC。 | 按本批出生归属清理，独立 NPC 保留；增加带无关 hook 出生的回归。                |
| 重新选格造成无端取消 | 猎场已经选好合法出生格，再执行一次选址可能因占位变化选出另一份名单。 | 重验证原来的格子是否仍合法、可达、互不重叠，不要求再次排序得到同一名单。       |
| 清理异常掩盖召唤异常 | 清理本身抛错时，最初的失败原因丢失。                                 | 合并清理错误并保留原始原因，继续处理可清理对象。                               |

此外，两个楼层的外层巢穴撤回原本可能在删除抛错时中断，跳过后续清理和取消。现在逐巢尝试清理，在 `finally` 中取消主题及人口计划，报告失败并保留原始原因。

前两种异常契约通过受控故障注入验证，不等于已观察到普通无其他 Mod 的游戏会随机抛出同类异常。重构中发现的实现缺陷在交付前修正；不把它们写成 test.86 的日常玩法故障。
