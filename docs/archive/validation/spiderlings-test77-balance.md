# test.77 玩家体验改进与原生数值模拟

日期：2026-10-01。候选版本：`0.92.36-test.77`。结论依据 KD 5.4.92 与当日获取的官方 5.5.3（`12a77c8b9e72dbbf9501aed12f1de839ac655eb6`）实际运行时；不修改官方游戏或玩家的已安装 Mod。

本版取消固定脱困次数，采用原生概率、速度、进度和体力结算。Lv1 约一次、Lv2 约两次、Lv3 再难一些、完整腿袋更强、茧明显最强是普通面板的校准目标，不能成为所有角色都必须满足的计数门槛。场地保留原队伍，回收增加接力，特殊楼层延后到首个 Boss 之后。武器和巢穴增援参数保留。

## 脱困：参数与结果

测试角色没有脱困特质、额外锁或收紧，起始体力充足。普通单件使用原生 Knife；真正无刀场景清空武器及切换历史。测试通过原生 `KDSendInput` 发出脱困与等待，完成 delayed actions，体力不足时等待恢复，不注入进度或指定成功结果。装备后调用原生零时间面板刷新，避免上一件装备的限制残留。记录中的“动作数”只统计实际脱困输入，“回合”包括延迟与休息。

每版主要校准 234 案例：五种单件 × 三种方法 × 十二种种子，加完整 24 件／无锋利环境／真正无工具三种场景 × 三种方法 × 六种种子。另覆盖全部 23 件普通蛛丝，每种方法三种种子，Lv2、Lv3 Arm 各扩展到十二种种子，每版 261 案例。手臂原生限制会额外降低效率，因此只给 Arm 单独的 chance 配置，不绕过其原生阻挡。单件与全套不能简单相加为固定脱困预算。

| 普通单件    | Cut 动作 | Remove 动作 | Struggle 动作 | 体验结论                               |
| ----------- | -------: | ----------: | ------------: | -------------------------------------- |
| Lv1         |        1 |           1 |             1 | 轻度束缚，普通角色可迅速处理           |
| Lv2         |        2 |           2 |             2 | 明确高于 Lv1                           |
| Lv3         |      2–3 |         3–4 |           3–4 | 高于 Lv2；切割最节省资源               |
| 完整腿袋    |        4 |         5–6 |           6–7 | 高于普通 Lv3，半成品按沉积比例连续减弱 |
| Cocoon 外茧 |        7 |           7 |             7 | 强度差距主要表现为耗时、体力和内层封锁 |

Lv3 Arm 的 Cut 在最终十二种子校准中为三次；其他 Lv3 的差异由原生部位、面板和随机结算决定。相同动作数也不代表相同强度。

| 对照     | Cut 回合 / 显示体力累计 | Remove 回合 / 显示体力累计 | Struggle 回合 / 显示体力累计 |
| -------- | ----------------------- | -------------------------- | ---------------------------- |
| Lv2 Legs | 约 5–7 / 4              | 约 5–7 / 10                | 约 5–7 / 60                  |
| Lv3 Legs | 约 8–9 / 4–6            | 约 11–14 / 15–20           | 约 12–22 / 90–120            |
| 完整腿袋 | 14–15 / 8               | 19–23 / 25–30              | 42–54 / 180–210              |
| Cocoon   | 25 / 28                 | 28 / 105                   | 76 / 315                     |

累计体力是各次原生费用之和，包含恢复体力后再次支出的部分，不是角色必须一次拥有的体力上限。Full 24 件开局在原生 Sharp 环境解除外茧后，仍保留全部 23 件内层；没有锋利环境且刀不可达时，Cut 被原生规则拒绝。没有刀和 Sharp 时也不获得免费的切割资格，Remove／Struggle 保留合法原生路径。

KD 的 delayed struggle 每个正时间 tick 有至少 `0.04` 的进度。只压低 chance 通常无法把合法脱困拖到几十次。当前茧采用更慢速度、体力费用倍率、移动限制与真实内层共同形成断档强度；保留“普通角色可以靠自身慢慢脱困”的方案。若今后改成普通角色必须借助环境或帮助，需要另行调整可行性规则，不能重新藏入固定次数门槛。

原生配置集中在 `WebbingData.ESCAPE_PROFILES`，以下顺序均为 Cut／Remove／Struggle：

| 配置     | escapeChance    | speedMult       |
| -------- | --------------- | --------------- |
| Lv1      | 4 / 4 / 4       | 1 / 1 / 1       |
| Lv2      | .18 / .30 / .12 | 1 / 1 / 1       |
| Lv2 Arm  | .18 / .70 / .20 | 1 / 1 / 1       |
| Lv3      | .10 / .14 / .04 | .75 / .65 / .65 |
| Lv3 Arm  | .18 / .50 / .15 | .75 / .65 / .65 |
| 完整腿袋 | .10 / .10 / .05 | .55 / .50 / .55 |
| Cocoon   | .50 / .04 / .03 | .10 / .20 / .24 |

这些 chance 是原生计算的输入，不能直接读作最终百分比。茧 Cut 的较高输入用于抵消完整受缚的原生惩罚，低速度仍使其显著更难。茧原生体力费用倍率为 2 / 3 / 1.5。其 `alwaysEscapable` 只适用于 Remove／Struggle，不授予 Cut 工具资格。普通束缚不强制可逃脱。

旧存档 Lv2／Lv3 动作记录按旧两次门槛转换为原生 `struggleProgress`，旧腿袋计数按其旧比例转换；保留更高的已有进度并封顶在完成阈值以下。转换不替换物品、不移除锁、不改变链接。查询、拒绝输入和读档不推进脱困。茧三次／十二回合的活动记录只供 WebCaster 后续真实命中加固，不再参与脱困成功结算。

## 场地、预警与回收

新围场优先尝试合法 9×9 外框，再回退到 7×7、5×5、3×3。较大围场留下 3×3 核心，以付费动作先完成外圈，再完成内圈。已有投入和队伍保留，不因拥挤把成员分流到其他空场地。施工边界不能穿过真实角色，核心也不能包住不可移动场景物。半径二的单圈扩建按真实外框计算下一圈，避免重复原圈。

施工面积增大意味着完成时间增加。单人原生施工场景预算相应扩大，测试要求真实逐格完成，不免费补建。狭窄地图仍可能选小场地；这是地形回退，不能承诺每层都有足够空间。共享玩家情报仍沿用 test.76 的原生感知和四回合有效期。

完整猎场验收还复现了旧队伍失去最后一个可行动成员后仍尝试选址的空坐标异常。现在新选址及失效重选都先确认存在可行动成员；空队伍保留历史但不生成无人施工的计划。成员恢复后继续按正常资格规划，已投入所有权不因暂时失能而分流。两项回归覆盖成员消失及全员失能时的地形失效。

Mage 坠牢蓄力由三回合改为五回合，成功爆发后仍冷却七回合。符文触发后的 NPC 预警由一回合改为两回合，玩家预警为 `2 + ceil(max(0, SlowLevel) / 2)`，触发时只采样一次。等待、零时间更新及后来增加减速不能延长倒计时。保留危险格、动作反馈和项圈失败提示，不显示队伍分工、未来围捕安排或捕获概率。

八个回收来源保留极难状态：没有撤离宽限期，也不降低抵抗体力或牵引强度。首次挂绳必须真实近战命中、兼容项圈和原生装备准入。之后同队、已登记离场且没有 NPC 专用职责的成员，可通过三格内且有原生 LOS 的现有来源付费接力；同一操作不能既接线又拉人。每次拖拽仍只由一个执行者支付动作。

接力图从实际接触玩家的来源向外遍历，失能、死亡、遮挡和断链使对应分支失效；远端互相连成环不能自行支撑。读档和零时间更新不能免费加入来源。玩家主动拆除的那个来源需要新的真实命中才能重新加入，避免立即接回；其他合格来源仍可按规则接力。NPC 回收保持原来的命中准入。外部 leash、物品身份与原生牵引所有权保持。

## 首个 Boss 后的猎场与巢穴

两版原生首个 Boss 位于第 4 层。新旅程的两个特殊修饰符从第 5 层普通节点起开放；不在 Boss 节点强插特殊地图。已有未访问的过早预告会修复，已访问地图保留。不是通过修改玩家 Boss 奖励或即时完成状态达成此门槛。

猎场继续使用原生 Maidforce 主派系人口机制。该修饰符的随机权重倍率为 Spider 9、Maid .35、Dressmaker .2、Nurse .2、其他 .1；这是候选权重倍率，不能等同于人口百分比。三个任务巢的十二只固定守军仍在，另有随机蜘蛛。取消普通猎物的成簇配置，普通新生猎物尝试在合法、可达的格子上留出六格间距，空间不足时接受可行位置；商店、预设、主从与专用任务单位不重排。

每版生成三种区域 × 八种种子，共 24 张 Maidforce 猎场：5.4.92 有 5–13 只额外随机移动蜘蛛，5.5.3 有 6–12 只。女仆和其他随机 NPC 均仍存在。另检查第 1–4 层的八个修饰符拒绝场景。早期未指定 Maidforce 的强制地图探针没有走真实猎场人口配置，已弃用，不能拿它当正式前后对比。

闲置野生蜘蛛复用巡楼搜索，实际交战仍需要原生感知。已有玩家追击、NPC 战斗、捕获、回收、包裹、巢穴守卫和付费施工职责优先；不会为巡楼抽走造好场地的 Spinner 队伍。

巢穴增援参数本次不改。每版进行一／三／五巢、各 100 回合的三个压力场景，五巢样本末段均为 17 个实体，其中八只 Spinner，Tunneler 在 5.4.92／5.5.3 分别为一／两只；该场景会触发安静退让，不能据此推断整局最高人口或长期扩张。要判断巢穴是否应再削弱，需要完整玩家路线、持续警戒和任务巢破坏顺序的更长模拟。

## 武器：保留强度，继续观察

每版先进行六种原生目标 × 六把武器 × 三种种子，共 108 个静态攻击对照。目标保留原生防御、抗性和生命；攻击上限三十次。静态对照只比较输出，不代表实战通关率。平均攻击次数包含到达上限的样本，不能解释为所有目标的平均击败次数。

| 武器           | 5.4.92 平均攻击 / 回合 | 5.5.3 平均攻击 / 回合 |
| -------------- | ---------------------- | --------------------- |
| Knife          | 13.00 / 36.78          | 12.89 / 36.22         |
| Sword          | 8.17 / 31.17           | 7.94 / 29.89          |
| MagicSword     | 7.83 / 27.67           | 7.83 / 27.72          |
| StaffBind      | 7.61 / 34.78           | 7.72 / 35.56          |
| Mage Tome      | 9.17 / 23.33           | 9.00 / 22.67          |
| Mage Silkstaff | 6.28 / 28.61           | 6.39 / 29.39          |

再启用原生敌人 AI，对三种目标、五把武器、六种种子使用相同攻击／追击／休息策略，共 90 个实战样本。原生意志降至二或六十回合终止。这是固定策略压力测试，不是资深玩家的最优操作：每把 18 场中，5.5.3 Sword 胜 7、MagicSword 胜 9、StaffBind 胜 12、Tome 胜 12、Silkstaff 胜 12；5.4.92 最终复测分别为 6、7、12、12、12。小样本与原生随机结算不宜外推为稳定通关率；两把 Mod 武器没有表现出脱离原生控制武器档位的胜率。

每版另测四种目标 × 三种爆发距离 × 六种种子，共 72 个范围样本。Silkstaff 的中心／内环／外环对普通 8 HP Maid 基础伤害约为 6／4／2、实际 Slime 约为 27.6／18.4／9.2；中心能令无护盾女仆进入无力状态，是强力表现。原生抗性、护盾、重甲和 Boss 并不承诺同样结果。技能法力基础费用四；施法当回合的回蓝会让净面板扣除约为 3.7，不能误判为少扣法力。对照原生 Fireball 费用十／power 十、SlimeBall 四／power 四、SlimeSplash 1.4／power 一，结合延迟、命中位置和抗性看待范围控制价值。

当前证据支持保留武器数值。后续优先观察狭窄通道多目标与连续补法力玩法；若出现持续压倒原生武器的收益，再调整中心绑定量或资源成本，不先全面削弱伤害。

实战扩展探针还遇到原生 Ribbon Wristtie、分段球塞、Maidforce 受缚图的缺失资源事件（5.4.92 三个、5.5.3 四个页面错误）。数字结果保留，这组探针不能作为全部原生 NPC 外观均正常的证明。Mod 的正式双版本验收另行验证武器付费、束缚和自有素材。此前被自有蛛丝／腿袋束缚时的空 `Items/.png` 请求，则已修复为仅不绘制该不存在的图片参数，保留原生攻击按钮和功能。

5.4.92 的普通目标巢／下楼场景还复现了随机原生 NPC 衣物 `Gothic/HemLowerBack.png` 缺失。该场景改为隔离随机遭遇、保留任务巢、守军、场景物与真实下楼转换；猎场人口场景继续保留完整人口。缺失游戏素材没有复制进 Mod 或修改官方安装目录，相关早期失败记录保留。这个修正不证明玩家遇到的所有原生 NPC 衣物都没有缺件。

## 验证与可复现记录

原生模拟脚本及 JSON 位于工作树的忽略目录 `.scratch/native-escape-redesign/`：`calibrated.js`、`families.js`、`arm-cut.js`、`weapons.js`、`weapon-combat.js`、`ecology.js` 及 `baseline/`、`github/` 结果。Arm 小范围参数扫描属于校准反事实，最终结果须由打包后的正常定义再次验证。正式可重跑的 `native-escape` 场景随仓库交付，覆盖普通面板、完整内层、真实无工具、查询无进度及旧存档迁移；`player-recovery` 覆盖付费接力、断根和实际追击，`mage-timing` 覆盖固定截止时间。

最终 ZIP、双版本运行证据和检查汇总记录于 [COMPATIBILITY.md](../../COMPATIBILITY.md)。这些场景验证已描述的行为；完整玩家新局和其他 Mod 组合仍是后续体验观察的范围。
