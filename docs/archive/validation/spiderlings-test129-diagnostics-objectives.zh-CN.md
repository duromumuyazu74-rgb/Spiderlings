# 存档诊断、猎场任务与图鉴调试

任务：[诊断工具 #131](https://github.com/duromumuyazu74-rgb/Spiderlings/issues/131)、[猎场 0/3 #132](https://github.com/duromumuyazu74-rgb/Spiderlings/issues/132)、[图鉴目录与调试 #133](https://github.com/duromumuyazu74-rgb/Spiderlings/issues/133)。

本轮落实复盘中的四项改进。只读存档工具枚举全部栏位、当前地图和世界地图缓存中的已访问房间，列出任务、场地阶段、存活 Nest 与 Spinner 数量及实体 AI 覆盖。原生回放工具使用隔离浏览器存储，从选定栏位返回指定已访问地图，沿用原生存档加载和返回楼层入口。回放输出只写当前 checkout 的 scratch 新目录。移除其他可移动 NPC 的隔离模式是显式调试选项，原始输入文件与桌面存档保持原样。

匿名保存场地回归保留一圈已有投资、一个原巢施工者与供给巢的三名 guard。通过总控实际请求借调，在损坏后存读档，再通过原生付费行动恢复边界、封口并开始捕获。旧 test.127 无法封口，test.128 在 30 个付费回合完成，场景已接入双版本原生套件。它复现旧现场的借调和 guard 组合，不包含私人存档或角色信息。

文件任务执行复用现有命令 runner，传递独立参数数组。UTF-8 文件读写保留中文与字面反引号，不经 shell 拼接。失败的命令阻止后续步骤；GitHub 身份读取失败、账号不匹配和回读不一致使用不同错误码。远端写步骤要求明确账号与回读预期，写后核对再继续。证据摘要只投影状态、场景与种子、轮数、阶段变化和有限证据路径，省略完整翻译、实体、命令状态和图片数据。使用方法见[开发文档](../../DEVELOPMENT.md#save-and-evidence-diagnostics)。

存档栏第 7 项的隔离回放复现绿色“0/3”：当前楼层没有目标 Nest，任务状态为 `cancelled`，原因为 `insufficient-space`，但 `EscapeMethod` 仍保留猎场类型。旧判定把没有有效目标当作放行。现在在原生 `calcEscapeMethod` 入口把取消任务的残留猎场类型恢复为 `Key`，由原生钥匙规则判定下楼；取消不增加完成进度，不重建已访问地图。有效任务及真实已完成任务保留各自状态，调试绕过也保留原有资格。原生强制逃脱类型与旧存档加载均有回归。

图鉴分类的“？？？”来自原生目录缓存早于 Mod 条目注册。登记完成后，从已有笔记刷新原生分类和条目，正常加载不赠送新笔记。`Spiderlings.Bestiary.unlockAll()` 解锁六项幼蛛条目，用于调试；保留其他原生笔记和已读状态，只把新解锁条目加入未读列表，重复调用不重复加入。随机笔记解锁仍使用原生机制。双版本场景覆盖已有单条笔记重新注册、全部解锁、六项中英图鉴绘制及日志／称号切换。

存档压缩沿用选定游戏提供的 `Scripts/lib/LZString.js`，本机核对版本为 1.4.4。接口依据该版本原生随附源码。未将该第三方实现复制到 Mod 或维护脚本中。
