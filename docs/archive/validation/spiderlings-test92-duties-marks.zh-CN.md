# test.92 施工、牵引与区域印记修复

本次接续 test.91 提交 `aa961fe`。用户报告 Spinner 在角落停步、连线后不拖回且攻击框残留、多层场地没有继续施工，并要求取消 NPC 结茧中的三步退场。Mage 持续区域应每回合叠层、按层数刷新更长时长，满层标记更亮。用户明确保留命中引爆清空层数。

## 实现

- Spinner 分组保留已付费场地。首个施工目标或工位被占时，尝试同层其他可执行任务，不跳过外层，也不免费建造。诱敌者在两回合没有自身路线进展或猎物靠近时转入主动施压。普通感知与正式 Capture 对抗分开，正式对抗才抢占附近工人的施工。
- 牵引接管行动时清除旧攻击预警和攻击点。原生路径的下一格被角色占用时，使用现有施工寻路避开占位；移动支付和玩家拖动仍由原生移动与 tether 完成。Capture 围拢也允许先远离目标再绕过障碍。
- NPC 自有蛛丝完全黏住，或自有蛛丝足以造成原生无力反抗时，正数抗性后伤害乘 4。原生格挡、护盾、击倒和死亡保留。取消三次行动后强制非致命移除，不再占用蜘蛛行动；旧存档仅丢弃倒计时。
- Mage Hex 每个有效区域回合补一层，上限三层，每次分别刷新 3／4／5 回合。保留命中消层和引爆间隔，补层及读档不再重置间隔。三层蜘蛛标记由 0.7 不透明度变为 1，并叠加 0.4 的加亮层；消层、过期或不可见时取消亮层。区域的两回合预警和三回合有效时间不变。

## 职责与存档

施工可执行性留在 `SpinnerAI`，拓扑模块保留外到内顺序。Recovery 与 Capture 复用既有地形、占位寻路，避免各自维护另一套地图规则。NPC 易伤由伤害事件判定，不再让战斗调度维护缠裹进度。

复制存档为第 796 回合奖励房，缓存中仍有第 3、7 层地图。该副本不能代表截图中尚未保存的每一帧。桌面游戏进程和原存档未修改；受控原生场景与存档观察分别记录，不把函数探针当完整游玩结论。
