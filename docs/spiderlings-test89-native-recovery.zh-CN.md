# Test.89 原生牵引与场地开口修正

本轮接续 test.88（`58ee6e3`）。用户要求牵引使用原生通道，按有效 Spinner 数量增加移动回合且不设上限，场地开口应随玩家来向调整。

## 调查与修改

新保存的现场位于第 436 回合，有 52 个实体。存档中的角色只有腿、踝普通蛛丝，没有腿袋或项圈，但保留五只 Spinner 的待回收职责。旧 `wantsPursuit` 没有检查锚点，导致不能挂绳的追击仍抢占施工；通道换向又被要求场地完整，破损现场一直得不到调整。修复版读取副本后，五只来源均不再请求无锚点回收，24 个等待回合中场地动作日志从 44 增至 61。原始存档未覆盖，也不提交到仓库。

普通围场现在根据不足四回合的可信目标观察重选入口，两次换向至少间隔八回合。调整入口只修改计划，打开新入口和封回旧入口仍需实际行动；已启动封口捕获的场地不再向外换向。破损通道可以继续按已知来向选择通口，维修与入口作业保留施工优先级。接管已有围场时使用实际 layer IDs，避免把已建边界误认为未施工计划。

玩家 Recovery 改为原生 `player.leash`。多只来源记录仍保存在 Mod 状态中，因为原生只有一个持绳者；由一个 executor 按原生敌人行动预算移动端点，原生 tether 负责拉动玩家、碰撞与提示。自有蛛网通过已有 Spiderling 原生穿网入口通行，玩家沿原生可通行路线被拉回。移除旧的独立操作栏、稳住动作、逐条计数拆线和私有跨网位移。

N 个有效来源在原有移动代价上增加 N−1 回合。因此正常速度下 1／2／4／8／12 只对应 1／2／4／8／12 回合的连续移动间隔，超过八只继续增加。使用原生保存的移动点数累积，避开原生返回 slow cost 达十回合后被调用者忽略的问题；冲刺不能绕过未偿还的移动回合。该数值取决于仍然有效且连接到玩家的来源，不等于场上蜘蛛总数。

原生拘束面板继续处理割断、拆除和挣脱。自有丝绳的每额外来源 0.05 原生逃脱惩罚保留。schema 1／2 存档迁移到 schema 3，保留真实物品 ID、锁、动态链接与进度。已有其他原生持绳者时不抢占；借用外部 leash 不改写物品内容。到达共同核心只释放本机制牵引，保留真实丝绳。NPC 回收和 Capture 的既有来源上限不在本次玩家移动改动范围内。

## 文本与验证

删除七个独立牵引 UI／逐条拆线反馈键；接线提示在英文和七语均去掉 `/8`，改为丝线绷紧可拉回，不承诺每个接线者下一行动都会拖拽。丝绳材质描述与 test.88 的武器特殊能力详情保留。

`player-recovery` 原生场景验证入口向东再向西换向并完成施工、1／2／4／8／12 来源的真实移动输入间隔、自动冲刺、12 来源的存读档、外部 leash 保留与原生移除，以及 1／4／12 来源下连续尝试走远仍发生原生拖动。两种自主逃场追击场景检查重新命中、接线、沿实际破口回到共同核心和结束回收职责。公开回归另检查 32 来源的无上限移动债务、现有减速叠加、失效来源、其他持绳者、付费接力和无感知时不追踪新坐标。

首次双版本运行发现测量夹具差异：5.5 会把当前原生持绳者的移动阈值降到一，增大基础移动费用无法固定该端点，蜘蛛提前拖回角色后正常清除了来源。移动间隔场景改用负的原生移动预算固定端点；独立的实际拖回场景继续使用正常预算，保留原生加速。此调整仅在私有测试脚本中，安装包未改变。

双版本最终包验收和本地交付结果记录于 [COMPATIBILITY.md](COMPATIBILITY.md)。原生测试使用隔离浏览器与当前游戏源码；没有替换运行中的桌面游戏，也没有把该结果表述为桌面壳或所有第三方 Mod 的兼容保证。
