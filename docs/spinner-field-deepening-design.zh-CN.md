# 场地 AI 深化设计

状态：已实现，test.132 完整双版本原生验收通过；具体参数保留为后续运行校准的起点。日期：2026-10-07。见[实现与验收记录](spiderlings-test132-field-lifecycle.zh-CN.md)。

基线为 test.131，提交 `175b99e`。决定见 [ADR-0025](adr/0025-field-duty-and-investment-retirement.md)，三轮回答见[访谈记录](spinner-field-deepening-interview.zh-CN.md)，术语见 [GLOSSARY.md](../KinkyDungeon-Spiderlings/GLOSSARY.md)。这份方案深化 [ADR-0024](adr/0024-layered-field-command.md) 的既有层级，调整其已投入工程默认持续保留运行的策略，不改变真实捕获、拉回和原生行动资格。

## 目标行为

总控持续比较现有覆盖与角色位置，优先选择有效拦截地点，再从有效候选中优先多层大围场。角色进入未完工场地时，场地 sub AI 保留施工者，其余有余力的 Spinner 承担牵制。唯一施工者求援并继续合法施工，不因目标贴近或受到攻击改成普通自卫。

持续停工必须有实际原因和恢复尝试。低价值小场地在存在明显更优且有真实施工人手的替代方案时可以退役，释放捕获场地名额；已有蛛网转为逐渐消散的残网。真实捕获或拉回仍在使用的场地不得因此退出。

## 职责与状态所有权

| module                 | 所属管理者  | 独占职责                                               | 接收的事实                                                |
| ---------------------- | ----------- | ------------------------------------------------------ | --------------------------------------------------------- |
| 持续工程规划与生命周期 | 总控        | 候选比较、有效覆盖、工程需求、进展、阻塞恢复、退役判断 | 位置、地形、实际工作、人手与承诺                          |
| FieldCommand           | 总控        | 唯一当前指挥、借调批准、途中任务、返还与改派           | 工程需求、供给场地可释放人手、真实到达与受阻              |
| SpinnerDuties          | 场地 sub AI | 一次原生敌人行动的最终职责和阶段许可                   | 有效指挥、施工 assignment、实际来源、原生合法性、离场资格 |
| Topology / NativeField | 执行事实    | 物理结构、损伤、施工支付与结果、残网消散               | 已批准的实际行动与正时间推进                              |
| 原生 Runtime adapter   | 接入        | 整理实际行动事实、执行已裁决职责、报告结果             | 原生目标、感知、移动、攻击与施法阶段                      |

三项深化不要求各自再增加一个公开 module。规划与生命周期共用一个深 module，生命周期是其内部 implementation；借调继续由 FieldCommand 独占。这样隐藏跨工程政策，而不是添加两个互相传递内部数据的 shallow module。

删除测试：删除工程规划会把投资、覆盖、退役与阻塞政策散回选址和借调调用者；删除 Duties 会把行动许可散回所有原生入口。两个 module 都应增加 depth。Runtime 作为 adapter 不保存另一份政策。

## 单次行动裁决

正时间原生敌人行动有独立行动身份，同一行动内敌人循环、移动、攻击和施法共享一个决定。世界回合身份不足以区分同一实体在一回合内的多个合法行动。原生阶段尚未产生所需事实时可以准备决定，但最终职责只解析一次。

裁决按资格排除和职责承诺处理，而不是在每个入口重新遍历优先级：

1. 死亡、失能、无合法行动和过期指挥排除当前执行；必要资格在实际执行前复核。
2. 已生效的玩家或 NPC 捕获、拉回来源继续履行真实承诺。既有本场地维修释放规则保留，不扩大成跨场地借走来源的许可。
3. 符合既有结茧离场规则的个体执行离场，不接收施工、普通牵制或追击；离场不能拔掉仍受保护的真实来源。
4. 有效在途或返回命令由总控约束，不能被个体自主追击覆盖。必要巢穴防御保留已有保护规则。
5. 已分配且合法的施工、封口或维修优先于普通攻击。唯一施工者继续施工并提出持续支援需求，求援拒绝不改变其施工职责。
6. 空余 Spinner 才承担牵制或明确委托原生攻击；无有效场地或总控命令时恢复自主行为。

施工失败返回具体原因，该行动不自动附赠攻击、另一次施工或额外移动。被攻击可能造成真实死亡、眩晕或合法工位变化，继续影响施工，不产生无敌施工者。

### interface

`decisionFor(actionFacts)` 返回本行动职责、允许阶段、指挥与 assignment 修订身份；`recordResult(actionId, result)` 接受唯一实际执行结果。方法名是实施建议，接口契约包括以下要求：

- Runtime 的所有原生 AI 类型共用此 seam，不再独立裁决结茧离场或普通防御。
- 来源资格由 Capture / Recovery 执行方提供，只读事实供 Duties 与 Command 共用，避免各自维护不一致的保护名单。
- 旧指挥或旧 assignment 的决定不能在新指挥下执行。行动尚未支付时使其失效，已支付结果仍归属于真实执行的旧任务。
- 一次决定只消费一次执行结果。只读查询、加载和零时间不执行行动。

调用者获得跨阶段 leverage，新增行为规则的 locality 集中在 Duties。测试从原生接入调用同一 interface，检查最终动作与支付，不只比较返回的职责标签。

## 持续规划与有效覆盖

每次正时间总控准备读取一个一致的世界事实快照。内部规划保留合法几何和路线的具体 implementation，调用者不再提供大组会修改工程内部状态的 callback。

规划顺序如下：

1. 复核既有工程、地形合法性、真实来源保护和当前人手承诺。
2. 按现有交战焦点和可达目标更新覆盖需求。全局位置知识只进入规划，不伪造原生感知或命中。
3. 对已有工程更新实际进展、维修和阻塞恢复需求；优先利用能够有效覆盖目标的工程。
4. 对未覆盖需求筛选合法候选。有效拦截来自当前位置或当前地形中合理的通行路线，不假定玩家下一次输入或未来位置。
5. 在有效候选中优先合法多层大围场，后备为有效通道和小围场；远处无有效覆盖的大场地不因面积大胜出。
6. 向 Command 请求实际可达且可释放的施工者。候选本身、求援意向或在其他工程工作的成员不计作新增工程承诺。
7. 已取得有效成员承诺且最终地点仍合法时，才启动新工程或批准替代。替代失败不能先退役旧工程。

覆盖分别描述“物理可用”“正在推进的预期覆盖”“当前无法恢复的等待工程”。不能因为存在一名理论上可施工者，就将一个长期没有进展的项目视为有效现成覆盖。

### interface

`prepareTurn(worldFacts)` 返回稳定身份的工程需求、工作意图及规划摘要；内部完成候选比较与生命周期重评，并通过现有 Command 的窄契约取得或更新成员承诺。`recordOutcome(outcome)` 接受实际推进、到达、受阻和失效；`inspect(projectId)` 只读返回当前状态与原因。

外部不写评分、工程状态、付费进度或临时成员名单。地形与执行 seam 使用已有 KD adapter，公共测试和原生测试提供相同意义的事实与结果；不新增通用策略插件或独立事件系统。

工程结果带有工程身份、修订身份和真实行动身份。已支付结果不能重复记账，也不能因指挥变更丢失；过期命令不能修改另一个新工程。新地点启用与旧工程退役在同一次总控提交中完成，过程中不出现两个有效指挥或超额活动场地。

## 工程生命周期与退役

| 状态        | 进入依据                                   | 后续处理                                                             |
| ----------- | ------------------------------------------ | -------------------------------------------------------------------- |
| approaching | 有合法选址和实际施工者承诺                 | 付费到达；调整合法路线或报告受阻                                     |
| building    | 有待完成工序并获得实际推进                 | 按拓扑工序分工，保留施工者                                           |
| usable      | 具备既有真实捕获几何资格                   | 按真实命中与来源规则封锁和捕获                                       |
| repairing   | 在用结构损坏且可合法修复                   | 保护真实来源，安排独立工人或既有合法维修释放                         |
| waiting     | 暂无可执行工序或有效施工者                 | 保留投入，换工位、换人、求援；报告原因                               |
| retiring    | 总控批准替代，且当前无受保护捕获或拉回承诺 | 结束新任务接收，关闭工程请求，撤销过期 assignment，返还或改派成员    |
| retired     | 退役处理已提交                             | 释放名额，停止该场地的自动封锁、捕获、维修和拉回目的地资格；保留残网 |

永久地形失效继续走既有合法失效清理，不能与普通 waiting 混为一类。完成度按去重后的付费工序衡量，不能用蛛网贴图数量或同心圈数量代替。已支付投入与当前损伤分别记录，维修不会伪造首次完工进度；改变预定开放口等合法工序修订要同步更新剩余工作。

### 相对价值与稳定期

按可解释的顺序比较，而不是把距离、面积、回合和人手强行汇成任意加权总分：

- 旧工程是否仍具有当前有效覆盖，新候选是否具有明确有效覆盖。
- 两者的可用规模与层数，已有完成进度，以及从真实承诺人手推导的到达和剩余施工工作。
- 新候选是否连续成立，是否已经有可执行成员承诺，是否可在上限内合法启用。

初始自动退役只针对小工程，大工程不作为低价值小工程淘汰。已经付费完成大半或全部完成的小工程增加保留倾向，但连续失去有效覆盖且有明显更优替代方案时仍可退役，避免三个旧小场地永久占满名额。没有更优替代方案时，停工本身不使工程退出。

初始明确优势可以是旧工程连续失去有效覆盖、新候选稳定形成有效拦截；若两者覆盖相当，则要求新候选规模明显更大且预计完工成本不增加，或同等规模下预计剩余成本明显下降。完成度保护、规模门槛与比较间隔是可调参数，见下表。

替代提交前重新复核旧工程是否已开始真实捕获或拉回、新成员承诺是否仍有效。任何复核失败都保留旧工程并反馈原因。上限为 0 时既有工程照常运行，但不得以先退役再替代的方式绕过禁止新部署。

### 残网与共享结构

退役残网保留实际形状和已有损伤，使用既有未激活蛛网的可破坏与减速表现，不产生新的独立屏障类别。共享同一结构的在用场地继续拥有其合法功能；只结束退役工程自己的拥有与调度关系。

退役按残网保留模式结束管理，保留仅由退役场地拥有的已付结构。生命周期区分结束管理、保留残网和最终物理清理；残网不能留在捕获几何或最近拉回场地的候选集合中。寿命耗尽后的拐角须正常付费重建，并恢复其有效结构标记。

无人依赖且无在用场地共用的残网随正世界时间衰减，生命值逐步下降，到寿命终点清理。仍被占用或被有效共享的结构暂缓最终清理；共享关系解除后才开始残网衰减。正常破坏仍可提前清理。退役不能自动撤销；以后再利用该地点必须重新通过合法部署、名额与真实施工流程，不能恢复一份旧指挥。

## 保存与旧存档

工程持久保存身份、阶段、计划修订、付费进度、最后实际推进时间、阻塞原因、候选稳定观察和退役状态。成员指挥与借调仍由 Command 保存。残网保存退役来源、已消散时间、损伤与有效共享关系。

旧存档缺少新增字段时，从真实结构和合法成员关系初始化；未知停滞年龄从当前时刻开始，不把加载当作长期停工而立即退役。残网计时不在加载或离线时间中推进。一次行动的职责缓存不保存，加载后重新生成；物品、捕获、挣脱与真实 tether 沿用现有身份和进度。

历史已投入超额工程仍保留，上限阻止新建；只有符合新退役条件的小工程可以退出。猎场原始目标 Nest 和任务进度不属于本设计的替代对象，不能借场地迁移重建或替换任务目标。

## 验收与实现次序

先统一 Duties 与所有原生入口，删除 Runtime 的重复优先级；再深化规划与生命周期，替换大组 callback；最后接入退役残网与保存迁移。每步都保留既有捕获、拉回、封口和支援验收。

| 场景                                     | 必须观察到的结果                                                       |
| ---------------------------------------- | ---------------------------------------------------------------------- |
| 唯一施工者，目标贴身并持续攻击           | 发出稳定求援请求；只要未失能且工序合法，实际付费施工继续               |
| 多名 Spinner，目标进入未完工核心         | 实际施工与牵制分工并存，不能全部改为普通攻击                           |
| 玩家结茧并安静等待                       | 所有实际原生 AI 类型依既有离场计时散开，Duties 不重新召回              |
| 工位堵塞、工人死亡或路线阻断             | 换工位、换人或求援；仍停工时可读到真实原因，不产生免费行为             |
| 近处有效后备与远处无效大围场             | 有效候选胜出；有多个有效候选时优先大围场                               |
| 低完成度旧小工程与稳定更优候选，上限已满 | 有实际成员承诺后进行一次合法替代；旧工程退出，残网保留，活动名额不超限 |
| 已完成小工程长期失去覆盖，上限已满       | 更长稳定期后仍可按明显优势替代，不因完工而永久占用名额                 |
| 旧工程正捕获或拉回目标                   | 即使替代候选更好也不退役，不丢失来源与进度                             |
| 角色短暂折返或新候选施工者失能           | 不反复重建；替代提交失败保留旧工程                                     |
| 残网与在用工程共用结构                   | 在用工程功能不受影响，最后共享解除后才衰减                             |
| 残网寿命边界与保存加载                   | 正时间逐步衰减、正常破坏有效、加载不免费消散或重放施工                 |
| 设置上限为 0，或旧档已有超额工程         | 0 不部署和替代，既有工程可运行；超额不误删，也不追加部署               |
| 多次行动、指挥变更与旧执行结果           | 同一次行动只支付一次；真实已付结果不丢失，过期指令不能操作新工程       |

公共验收跨同一 interface 检查状态与支付结果，双版本原生验收从真实敌人循环观察行为。性能对比使用同一地图、种子、人员与玩家行动，记录候选扫描、寻路次数和回合耗时；没有原生对照之前不声明“已解决卡顿”。
