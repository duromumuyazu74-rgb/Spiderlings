## 管理层级与内部职责

总控仍拥有最高调配权，场地 sub AI 仅指挥 Spinner，其他移动 Spiderlings 本阶段仅接受总控的区域目标。以下 module 属于现有管理层的内部 implementation，不增加指挥层级。

| module               | 所属管理者   | 唯一负责的决定或状态                                           | 依赖的既有行为                                  |
| -------------------- | ------------ | -------------------------------------------------------------- | ----------------------------------------------- |
| 场地借调与归属管理   | 总控         | 成员承诺、当前指挥、原场地关系、支援与返还责任、撤销和失效清理 | 供给场地的可借成员判断、来源资格和实际执行结果  |
| 捕获场地工程管理     | 总控         | 持续需求、覆盖比较、已承诺工程、维持与修复、追加建设和真正失效 | 合法候选、地形、实际可达性与 Topology 施工结果  |
| Spinner 最终职责裁决 | 场地 sub AI  | 本次原生行动的具体职责、允许的原生阶段、等待或明确委托原生行为 | 实际捕获与回收职责、必要防御、合法任务和工位    |
| 原生执行与结果适配   | Runtime 接入 | 合法移动、命中、施工支付、牵引及各物种既有技能的执行结果       | KD 原生机制、Capture / Recovery、NativeField 等 |

工程管理不能直接改成员指挥归属。借调管理不能修改捕获计数、编织进度、物品身份或 tether。场地 sub AI 不能通过更改物理 owners 抢走其他场地的 Spinner。

## 1. 借调与归属拥有完整生命周期

### 身份与权威

物理场地拥有关系与当前指挥关系分别表达。一个 Spinner 可以保留原场地物理拥有关系，但同一时刻只能接受一个场地 sub AI 的具体指挥。

总控内部的借调管理 module 是成员承诺和指挥转移的唯一维护者。供给场地提供可借成员，不能在提供后自行修改接收场地名册；接收场地提出需求，不能直接写供给场地的归属。

其他移动种类的区域调配也使用总控的唯一成员承诺原则，但不进入场地 sub AI 的 Spinner 名册，不具有另一份场地指挥关系。

### 正常路径

1. 需求场地提供任务需求，总控根据已有优先原则处理。
2. 总控询问供给场地，供给方按当前实际职责与必要人手返回可提供成员或原因。
3. 总控复核成员仍可释放、真实可达且未承诺给其他需求，然后授权派遣。
4. 成员到达后由接收场地安排 Spinner 工作。批准和到达不是完成任务，也不产生免费位移或施工。
5. 支援完成后向总控反馈，总控安排返回或重新分配，归属变化由同一处完成。

一个成员被首个需求正式承诺后，不能在第二个请求中再次提供。部分满足记录已派人数与剩余缺口；尚未派出的缺口不是已承诺的成员。

### 状态变化与结果

供给批准后、派遣执行前若成员进入必须保留的实际职责，则本次批准已经不再可执行。总控释放该次尚未执行的承诺，继续询问其他可借成员或返回剩余缺口与原因，不能强行拔掉来源。

成员失能、死亡、接收场地撤销、原场地失效或路线不可达，统一进入借调管理的重评与清理。已经实际参与捕获或拉回的成员仍遵守此前确认的职责保留规则。

保存与加载保留当前指挥、原场地关系、任务状态和返回责任。加载只审查关系是否仍有效，不重放派遣动作，也不再次添加来源或施工。

### interface 与 seam

外部调用者只需要提交需求或供给判断、查询当前有效指挥并报告实际结果。批准、承诺、撤销、返还之间的顺序约束收进同一 implementation。物理 owner 的 native adapter 根据有效关系投影，不再从当前指挥名单直接覆盖原场地拥有者。

此 seam 的 depth 来自隐藏完整转换规则，locality 集中在借调管理；同一套约束服务新建、维修和控制支援，形成 leverage。

## 2. 持续需求与已承诺工程共同管理

### 规划对象

角色实时位置是持续更新的规划事实。候选位置是可以比较的地点；捕获场地工程是已经选定地点并安排建设的持续事项；实际蛛网是 Topology 管理的物理成果。三者不能混为同一种可随时替换的数据。

工程管理 module 每次评估要同时考虑已有覆盖、工程状态、实际可施工成员及已承诺工作。不能因某个角色走了一格，就另建一个相同覆盖的工程，也不能把已经安排在其他工程的成员再次计为自由人手。

### 决策顺序

1. 审查现有工程和实际物理成果是否仍合法。
2. 用当前角色位置重新比较需求与已有覆盖。
3. 优先安排已有工程推进、合法维修与必要补员。
4. 对仍未覆盖的独立需求比较合法候选，并向总控请求施工成员承诺。
5. 只有真实可达、可施工的成员被正式安排后才启动新工程。

普通位置变化更新工程价值，不直接清空已付进度。地形不再允许合法重建或总控明确撤销，才按已确定的生命周期结束工程。暂时占格和单条路线受阻不能被误判为地形永久失效。

合法通道与围场候选、大小回退和 Topology 的工序语义继续复用。已有地形缓存按真实地形变化更新；角色位置更新不能伪装成地形全部失效。未付费接近的既有进展保护与已付工程保留规则要由工程管理集中解释。

### interface 与 seam

工程管理的 interface 表达需要维持、修复或追加的工程决定，调用者不必组合分散的评分、投入检查和弃建条件。规划 seam 复用现有地图和 native adapter；工程 implementation 负责跨工程规则，而不是仅包装候选评分函数。

depth 来自需求与承诺联合判断，locality 集中投资保护和新建条件；首次布局、追加与无场地回收复用同一原则，获得 leverage。

## 3. 最终职责跨原生入口生效

### 调度与执行

受指挥 Spinner 的职责由场地 sub AI 一次裁决，Runtime 的敌人循环、移动、攻击和施法入口读取同一有效决定。具体入口执行该职责或报告不可执行，不各自重新招募、改派或抢占建设成员。

实际 Capture、Recovery 与必要防御是裁决输入，保留原先确定的保护规则。场地施工与维修由 Topology 提供真实可执行工作，再按当前工位、占格和原生路径复核。

既有场内维修分工仍保留。玩家 Capture 有多名有效来源时，合法维修可按现有规则调出一员，并至少保留一名实际来源，保留编织与物品进度；NPC 已有来源不因此拆除。这项本场地维修例外不能扩大成供给方可跨场地借走实际来源的许可，其判定迁入职责裁决，执行状态仍由原实现维护。

职责决定本次允许做什么，原生执行决定动作是否真实成立。不能因为计划安排了施工，就认为已经支付或完成；不能因为借调的名册改变，就认为已释放来源。

### 原生阶段约束

施工职责不能在后续攻击或施法阶段被另一个入口自动改成追击。若 sub AI 明确选择原生施压或防御，原生阶段按该决定执行。未纳入场地指挥的 Spinner 继续沿用既有自主行为。

真实执行时目标、地形或成员资格已变化，则返回无法执行或需要重评的结果。该行动不能顺便从旧短路链获得额外免费行为；允许的回退必须属于明确裁决。

非 Spinner 的本阶段命令只有区域调配，其物种已有法术、冲刺与建巢状态继续由既有实现结算。场地 sub AI 不为这些物种创建新的战术职责。

### interface 与 seam

职责裁决 module 的 interface 提供当前有效职责及接受执行结果，内部 implementation 隐藏优先规则和原生回退选择。Runtime 与 native adapter 通过同一 seam 使用它，测试从真实运行入口验证跨阶段行为。

这让维护具有 locality，同一职责具有跨阶段 leverage；删除旧入口各自改派和维修让步的规则，才实际增加 depth。

## 依赖与持久状态

策略、归属和工程管理属于进程内状态。原生执行使用现有 KD 接入及真实 Runtime 测试环境，不新增通用事件总线、远程调度或物种策略插件。

总控的世界级准备只生成规划与有效指挥；实际行动仍在对应的正时间原生行动内支付并执行。行动结果再用于归属和工程重评。零时间与加载只有状态审查，不推进建设、移动、加入或出生。

持久保存的是工程与指挥承诺、借调及返还责任。每次行动的暂时裁决由加载后当前状态重新生成，不重放上一次行动。独立来源计数、物品状态、拓扑损伤及施工信用继续按原有保存机制保留。

## 可供实现的 interface 契约

下表约定调用者需要知道的行为，不固定 JavaScript 文件名或参数拼写。三个 module 的内部名单、评分、状态转换和原生短路规则不暴露给调用者。

| module     | 调用者提交的内容                                      | 可观察的结果                                     | 调用限制                                           |
| ---------- | ----------------------------------------------------- | ------------------------------------------------ | -------------------------------------------------- |
| 借调与归属 | 场地、需求种类、所需人数、当前任务和原有请求身份      | 满足、部分满足或拒绝；已承诺成员、剩余人数、原因 | 同一持续需求更新原请求，不能重复创建承诺           |
| 借调与归属 | 某次支援的真实到达、完成、受阻或失效结果              | 当前唯一指挥及下一目的地，或等待重评             | 成员身份与支援身份须仍匹配；旧结果不能改写后来任务 |
| 借调与归属 | 查询成员当前有效关系                                  | 原场地、当前指挥、有效任务与返回责任             | 只读查询不派遣、不释放来源、不修改物理场地         |
| 工程管理   | 当前角色位置、合法地图事实、已有工程及真实可用人手    | 维持、修复、追加、等待或结束的工程决定           | 候选比较不改变物理蛛网；新增工程须取得成员承诺     |
| 工程管理   | Topology 与 native adapter 的真实推进、受阻或失效结果 | 更新后的工程状态及未满足需求                     | 不能把预订工位、到达或候选评分记成付费进度         |
| 职责裁决   | 成员、当前指挥和本次原生行动身份                      | 一个有效职责，及允许执行的原生阶段               | 同一次行动的入口共用决定，不能各自抢占或改派       |
| 职责裁决   | 原生执行成功、受阻、失效或已经支付的结果              | 完成记录、等待或后续重评需求                     | 已支付结果只记一次；失败不自动获得另一份行动       |

依赖通过进程内参数提供。地图、源资格、真实路径与付款结果使用已有实现；测试使用现有 KD 运行环境在相同 seam 提供可控情景，不新增仅为测试存在的评分 interface。

### 支援请求的理由与重试

请求身份由需求场地与持续任务确定。新成员或路径变化更新同一请求；任务消失后关闭，不能用过去的拒绝阻止新的合法需求。供给回复只是当下可提供人选，正式承诺前由总控再次复核。

| 内部理由         | 真实含义                                           | 重新评估的依据                     |
| ---------------- | -------------------------------------------------- | ---------------------------------- |
| 无可提供成员     | 没有符合条件的活成员，或所有供给场地均无法提供     | 新成员到达、生成或恢复行动资格     |
| 必要职责不可释放 | 实际捕获、拉回、必要防御或最低施工维修人手需要保留 | 对应职责结束或本场地新增足够人手   |
| 已承诺其他任务   | 人选已经接受其他有效调配，不能再次计入供给         | 先前任务完成、取消或释放承诺       |
| 当前不可达       | 没有供给成员能够通过合法路线到达需要区域           | 路线或占格变化使路径可用           |
| 接收任务已失效   | 场地撤销、永久失效或原需求已结束                   | 关闭本请求；新需求创建新的请求身份 |

部分满足也返回剩余缺口的原因。等待时间从首次有效请求保留，不能因每次更新而清零。内部理由用于诊断和调度，不把设计方针或详细 AI 决策浮字显示给玩家。

### 成员承诺的状态转换

供给同意后，总控正式承诺才占用成员。支援经过前往、执行、返回三个阶段；受阻是当前阶段的等待状态，保留任务身份，不凭占格就立即销毁任务。

| 转换             | 唯一维护者须完成的处理                                                             |
| ---------------- | ---------------------------------------------------------------------------------- |
| 可提供到已承诺   | 复核当前资格、路线、可释放职责与唯一性，同时记录原场地和接收场地                   |
| 已承诺到前往     | 交给接收场地唯一局部指挥；总控的派遣目标约束途中行为，原场地停止给此成员发具体职责 |
| 前往到执行       | 以原生真实到达确认；接收场地安排本地 Spinner 工作                                  |
| 执行到返回       | 确认需求已完成且成员可释放，总控解除接收场地指挥并安排返还                         |
| 返回到本场地工作 | 真实到达并确认原场地有效后，恢复原场地指挥；无效则由总控重新分配                   |
| 任一阶段失效     | 清理过期承诺与指挥引用；真实来源按自身规则保留或失效，不能仅因任务取消强制清空     |

受阻时先尝试合法路线。没有当前可行路线时向总控报告，保留已付工程并等待状态变化，或按已有优先级合法返回、改派。供给方告急只能向总控提出需求，不能越过总控召回仍受接收方指挥的成员。

借出者的原场地物理拥有关系不随前往、执行或返回阶段删除。接收场地施工成果按既有物理规则登记；临时支援不会把原场地整体转给接收方。物理拥有关系允许与指挥不同，不能反向从 owners 恢复一份竞争指挥。

接收场地可登记实际接受支援的 Spinner 为临时物理拥有者，关系随有效支援保持。支援结束后只解除这份临时接收关系，保留原场地关系及其他独立有效拥有者；借入者没有因此获得接收场地的永久归属。不能用完整当前指挥名单覆盖所有物理关系，也不能仅为维持 sub AI 存在补造拥有者。

若接收场地原有人手全死，最后的借入者完成可释放任务并返回后，接收场地可以真正进入既有无主衰减。只要合法重建仍可行，其 sub AI 保留需求并请求补员。保留逻辑计划与保留永久物理蛛网是两种结果。

返回阶段和场地失效后的过渡改派由总控的有效移动承诺约束，Runtime 调配 adapter 执行真实移动；未进入新的场地指挥前，不回退到 Spinner 自主追击。返还完成或总控合法取消承诺后，才恢复原场地指挥、接入新场地或回到自主行为。这只使用最高层调配权，不新增局部管理者。

## 总控一次评估的处理顺序

1. 读取当前楼层地形、所有相关角色位置、成员行动资格和真实来源状态。先审查失效关系，避免死亡成员或被撤销场地继续占用承诺。
2. 工程管理比较覆盖与现有投入，场地 sub AI 汇总缺员、维修或进入场地目标造成的支援需求。空地图仍比较基础通路建设，不等待首次看到猎物。
3. 总控按紧急防御与实际捕获或拉回缺员、维修、新建扩张的先后处理请求。同级比较合法路径距离与原有等待时间；完全相同使用稳定身份排序，避免每次遍历改变结果。
4. 借调管理询问供给场地并逐次承诺真实成员。已经承诺的人手立刻从之后请求的可用量中扣除，不能把多个工程的评估结果各自当成免费人手。
5. 工程管理接收实际满足量，推进已有工程或启动有施工成员的新工程。未满足需求保留等待状态，不能先画出已完成场地再补人。
6. 场地 sub AI 按有效指挥安排职责。Runtime 在该成员真实行动入口执行并反馈；总控读取反馈用于后续评估，不额外触发一次行动。

这是同一总控内部的处理顺序，不能把 module 之间的反馈实现成会反复调用敌人循环的递归调度。

### 工程状态与选址稳定性

| 状态       | 含义与允许的变化                                                                 |
| ---------- | -------------------------------------------------------------------------------- |
| 候选       | 尚未取得成员承诺；可以随角色和覆盖变化重新比较，不保存为已建设工程               |
| 接近施工   | 有合法位置与已承诺施工者，但还未付费；沿用现有接近进展保护及合法改址规则         |
| 建设或修复 | 有真实付费投入或待恢复的既有场地；角色位置变化不能直接迁移这些成果               |
| 可用       | 可以覆盖对应需求；仍审查拓扑破损、捕获准入和人员缺口，不永久忽略其他区域         |
| 等待       | 人手不足或暂时受阻，保留合法工程与真实投入；可请求补员并在相关状态变化后恢复     |
| 结束       | 总控撤销或地形永久不允许合法重建；结束指挥与工程承诺，物理结构按既有退役规则处理 |

每次先对比已有可用场地、待修复场地和已承诺工程的覆盖，再评价新增候选。初始基础场地优先拦截合法通路并考虑真实到达距离，围场作为回退；后续根据当前角色位置与未覆盖需求追加。工程数量由真实独立需求、合法地点和未重复使用的施工能力决定。

同一新地点在人手不足时只是候选或等待的需求，不能不断创建新的持久工程。合法已付工程不因需求短暂下降自动报废；保持、修复或撤销由同一工程管理作出决定，并能解释对应原因。

等待工程的规划范围不等于当前可用覆盖。工程管理结合真实到达、恢复可能性与已承诺人手判断它是否能承担当前需求。暂时受阻先保留等待；当前确实无法承担时，可以使用其他现有场地或评估独立替代位置，同时保留原工程身份与投入，不能在同一地点复制一份工程冒充追加。

## 职责跨原生阶段的有效性

本次职责带有成员、有效指挥、任务身份及原生行动身份。Runtime 的敌人循环、移动、攻击与施法入口验证这些身份仍匹配后，消费相同决定。来源、地形或目标在中途变化可让决定失效，但不能让另一个旧入口自行改派成员。

| 职责种类                   | 原生执行约束                                                                   |
| -------------------------- | ------------------------------------------------------------------------------ |
| 建设或维修                 | 只走真实工位和付费施工路径；其他阶段不能自动抢去追击                           |
| 捕获或拉回                 | 沿用现有合法来源、真实命中、持续回收与 tether 结算；不能以名册变化替代这些状态 |
| 必要防御或明确委托原生施压 | 按已允许阶段走既有原生行为，不改其感知、技能、命中或消耗                       |
| 前往、返回或工位移动       | 只通过当前合法原生路径推进，抵达不自动折算为施工或技能成功                     |
| 等待                       | 没有免费施工、捕获加入或额外移动；相关状态变化后再由管理者重评                 |

实际来源保护与必要防御先于可暂停施工。没有这些例外时，场地命令覆盖 Spinner 自主抢目标。没有有效场地指挥且没有总控移动承诺的 Spinner 使用既有自主逻辑；返还或过渡改派按总控有效目标移动。非 Spinner 仍只有总控区域目标，并保留自身已承诺技能的原生结算。

已支付行动不能撤回为未支付，也不能在反馈后再执行另一个职责。未支付但任务失效时返回重评结果，本次若允许原生回退，必须是职责裁决预先许可的行为，并仍受原生预算限制。

## 存档迁移与实现顺序

### 持久数据与派生数据

持久数据保存稳定场地与工程身份、有效成员承诺、当前指挥、借调原场地、返回责任和请求等待起点。物理 owners、损伤、施工信用和实际来源继续由其已有状态维护，不复制成另一份可相互覆盖的进度。

候选评分、供给快照、路径缓存与本次行动职责是派生数据，加载后重新验证。总控只审查状态，不在加载或零时间内派人、移动、施工、添加来源或出生。先清理无效身份，再生成下一次真实行动所需的决定。

旧 test.99 存档中的合法队伍和工程映射为对应的场地 sub AI 与工程，保留原物理引用和来源记录。原成员首次映射到其有效场地指挥，不补造历史借调；旧存档没有的支援和返还记录初始化为空。没有合法对应关系的成员继续既有自主行为，由后续正时间评估正常处理。重复加载不能重复登记成员或重放施工。

### 实现分批，但交付整套行为

1. 先实现唯一成员关系与借调生命周期，打通查询、派遣结果和保存加载；改掉“当前名册直接覆盖物理拥有者”的歧义。
2. 接入职责裁决及全部 Runtime 原生入口，让既有施工、维修、捕获和回收通过同一决定执行。此时先复用原选址，不混入新规划变化，便于定位行为回归。
3. 再实现持续需求与工程管理，统一首次建场、追加、修复、投入保护与无场地回收重建。接入非 Spinner 区域目标和 Nest 的既有合法协作。
4. 最后验证完整楼层情景、旧存档迁移及同一最终 ZIP 的双版本验收。分批是实现顺序，任一中间批次不作为完成整套架构的交付。

## 删除与替换清单

- 替换用单一成员名单同时代表当前指挥与原场地拥有关系的逻辑。
- 替换各场地直接转移彼此名册，再由全局审计修补的做法。
- 集中新建、维护、弃建与投入检查，删除分散的回收重建特例和重复条件。
- 让旧 Capture / Recovery / beforemove 等入口消费既定职责，删除反向维修分配特判与独立改派。
- 保留 Topology 已集中完成的工序规则、真实执行资格和原生结算。
