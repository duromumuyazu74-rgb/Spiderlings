# ADR 0003：拘束重构仅面向新存档

- 状态：已采纳
- 日期：2026-07-27

## 背景

ADR 0002 曾选择为旧的 Spiderlings 拘束 ID 提供存档迁移。但新五模块拘束族会同时替换规则、素材组织、升级路径与装备目录；迁移层会把旧碎片化设计长期带入新代码。

## 决策

拘束重构仅支持新存档。旧 Spiderlings 拘束实例和旧 ID 不迁移、不保留兼容 adapter。新代码可使用干净的 Spiderlings-owned 新目录与 ID。

## 后果

- 删除旧拘束和图片时无需维护旧存档的映射、幂等标记或回退路径。
- 新状态机只表达当前 9 件 Lv1、物理并存的 7 件 Lv2 与独立 Cocoon，不承担旧 LooseWebbing、五模块或完整／重度链语义。
- 使用旧 Spiderlings 拘束存档的玩家需要在重构前自行完成当前流程，或从新存档开始。

## 后续修订

ADR 0005 最初用八件 Lv1 替代五模块，后续 split-mitten 修复又把合并 Mittens 分成独立左右手，使当前目录成为 9 件 Lv1；ADR 0006 的物理并存范围相应收敛为 7 件无口部 Lv2。这些修订不改变“仅支持新存档”的核心结论。实施时应注销全部旧 restraint/model ID，不提供别名或热重载兼容，并用全新进程 denylist 验证旧注册没有残留。
