# 资深 KD 玩家模拟反馈：Spinner 对抗审查

这是脚本驱动的资深玩家策略模拟，不是真人试玩反馈。先看原生行动轨迹，再定位实现。实际游戏运行、原生函数探针和静态解释分别标注；自动验收通过不替代玩法判断。

本次起点是 `9de47ba` 的 `0.92.36-test.80`，SHA256 `4cf0e33e8322cd03f8978d9816d250a5aa67b11abf50b84ddd0edfef0cb913d1`。修复复测使用同一个 `0.92.36-test.82` ZIP，SHA256 `20a57bc18d65cdd1644acee29a4ac6d44a3b91d77d118ae7231a3d697ae5766b`。最终鼠标操作和查询分别在官方 KD 5.4.92 与新获取的 GitHub 5.5 提交 `29219e97a362228e64d885fb569b1b35ec74b3ef`（运行时 5.5.3）验证，未修改官方游戏。

## 角色、地图与证据边界

主要对照角色：楼层 0 原生测试夹具，无专长、无初始束缚、Knife；体力 `10/10`、法力 `15/15`、意志 `10/10`，游戏显示为 `100/100`、`150/150`、`100/100`。地图是 36×24 有边墙的开阔房间，初始玩家 `(23,10)`；三个 Spinner 在 `(18,10)`、`(12,7)`、`(12,13)`，原生识别从 `aware=false, vp=0` 开始。场地中心 `(14,10)`，外圈 9×9，边界 `(10,6)…(18,14)`，门 `(18,10)`。这是确定条件的遭遇夹具，不能直接当作随机巡楼的复现率。

11 种策略各用种子后缀 `0/1/2`，完整种子是 `adversarial-spinner-{策略}-{后缀}`，每组 64 个脚本行动步骤。移动调用原生 `KinkyDungeonMove`，等待支付原生时间；受阻移动步骤不能统称为付费回合。路线不使用法术或补给；初始消耗品和职业未逐项记录，因此不据这组夹具推断整局资源续航。专项核心站桩补验直接记录实际 tick、SlowLevel、MovePoints、资源、原生攻击与最终拓扑。

回收鼠标夹具另用种子 `spinner-ui-player`：同为楼层 0，无专长，Knife、BasicCollar、真实 SpiderlingsSilkLeash，三条来源；原生破坏已建 3×3 圈边界后放置在 `(16,10)`，来源 `(17,9/10/11)`。玩家破边使用真实原生攻击；起始位置和初始成功挂绳由夹具准备，不声称它们来自一次完整游玩。

33 组在 64 步内都没有 Capture。这个数字只描述上述未完工/外侧场地夹具，不能据此判定完整猎场或八来源回收容易。已建场地捕获、最大场地外到内施工、1/2/4/8 工人保留原队修复、六种 Spiderlings 原生共享感知、四个正回合信息过期，复用既有 `spinner-work`、`spinner-perception`、`player-recovery` 原生证据；本轮相关验收继续覆盖这些行为。狭图方案和不同构筑的整体结果在主报告中合并。

具体模拟感受：换向和绕柱能让我保留主动权，蜘蛛没有永远只在舒适距离旁观；短暂离开近战圈后继续停留，则会逐层缠上腿、脚与脚踝。原生识别与信息过期让断视线后的撤退有意义。原 test80 回收的最大困惑是：装备和来源都是真的，设计也写了站稳、单拆来源，但屏幕上根本没有这些动作；通过测试接口付了拆绳费用时，还可能完全没有进展。

最终鼠标序列 `Stand → Select → Remove → Remove → Cut`：回合增量分别 `1,0,1,1,1`，来源数 `3,3,3,2,1`。Remove 与 Cut 分别支付原生 5、2 显示体力；三来源 Stand 付 9 显示体力，其回合含原生恢复，净下降 4.5，不能把净变化当动作价格。拆源反馈明确为丝线松动或解脱，覆盖原生因压制载体脱出而显示的 Impossible。连续绘制触发的 114/90 次原生 HUD 查询没有资源、回合或来源状态变化。

## 待决定：未完工核心可重复停工

额外使用最终 test82，在相同三种子夹具中把玩家直接放在 `(15,10)`，连续等待 512 个真实原生回合，再向东走六次。三组均只付过最初 4 次建造；最终最内圈和中圈仍 `preparing`，外圈 `sealing`。最内圈四角全部未建、四段丝线 builtCells 均为零，`captureGeometryReady=false`。三个 body assignment 仍保存，但已有工人都追到玩家旁边近战，之后没有执行这些工作。

每局记录 757 次真实原生绑缚命中和 757 次 `0.05 tickle` 伤害调用（总原始伤害 37.85，不能等同意志损失）。束缚在腿、脚、脚踝的 L1/L2/L3 九件后饱和。512 回合后意志为 0，体力仍 10、法力 15；实际 SlowLevel=0、MovePoints=0。三组都没有 Capture，且随后六次移动均一回合走一格、体力维持 10、未被拉回或捕获。64 回合的核心/外门/外侧等待九组也有相同自由撤退结果。

静态原因与运行结果一致：AI 的“已识别猎物在共同核心内”分支在 body assignment 前让每个成员转追击/原生近战；它没有区分最内圈尚未建好。Capture 实际要求玩家位于最内圈内且该圈闭合，所以这些近战不会补上缺失的场地控制。敌人确实不断攻击，这不是无行动；玩家能反复利用的是全组施工职责被压制。代价是九件下身束缚和意志耗尽，附近 Mage/NPC 扩大战斗时风险仍可能很高，但本组三 Spinner 512 回合也没有将玩家留住。

推荐方向：保留提前侵入、真堵工位、击杀/推开 builder 的反制；在最内圈尚未形成控制时，由 lure/实际近战者维持压力，已指派且未接触玩家的 bodybuilder 继续原生付费施工。不要散队，也不要凭空完成边界或额外增加绑缚。如果坚持个人识别后全员近战优先，应接受这项可重复停工/自由撤退行为并明确它是选择。该优先级涉及既定方向，本轮代码冻结后未擅改；推荐方案仍需原生对照验证其能完成近核心工位，不能仅靠给代码加条件宣布有效。

冻结后的 scratch 对照补充：仅覆盖 AI 源码，在几何未闭合时让非 lure 的 body assignment 不进入统一核心近战分支，仍保留 adjacent native-defense 与 gate priority。5.4.92 六组（核心三种子、实占内门三种子）各 160 原生回合：核心施工从原版固定四次增加到 19/19/16 次，但内圈/中圈仍 preparing、geometryReady=false、Capture 0/3；六次撤退走五格，首次撞工作/敌格。实占内门组三场 paid=11、outer ready、内层 preparing，Capture 0/3，六回合走六格。因此“远端继续施工”能推进，尚不能解决近工位时再次转近战的停工；接触中的施工优先级仍需方向决定。该试验没有进入交付包，原始结果为下述 `aiProposal` 文件。
